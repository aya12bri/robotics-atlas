1.1 Units

A number without a unit means nothing. We always compute in SI units and convert at the end:

Worked example

A motor turns at 150 rpm. In rad/s: ω = 2π × 150 / 60 = 15.71 rad/s. If it drives a wheel of radius 0.05 m, the robot moves at v = r ω = 0.05 × 15.71 = 0.785 m/s = 2.83 km/h. The key formula of the whole course is this one: ground speed = wheel radius × wheel angular speed.

Pitfall: degrees and radians

Calculators and code use radians in sin, cos and angular speeds. If you type 90 into a radian function you get nonsense. Rule: work in radians, and convert to degrees only to read or to display (× 180/π).

1.2 Angles and trigonometry

An angle can be measured in degrees (a full turn is 360°) or in radians (a full turn is 2π ≈ 6.283). The radian is natural because of the arc length: on a circle of radius r, an angle θ (in radians) cuts an arc of length

s = r θ

This is exactly what a wheel does: when it turns by Δφ radians, its contact point rolls a distance r Δφ on the floor. Odometry (lesson 14) is built on this single line.

Sine and cosine give the coordinates of a point on the unit circle (radius 1) at the angle θ from the horizontal axis. Remember a few values:

θ0°30°45°60°90°
cos θ10.8660.7070.50
sin θ00.50.7070.8661

The reverse question, “which angle has this x and y?”, is answered by atan2(y, x). Always prefer atan2 to arctan(y/x): it knows the quadrant. Example: the vector (−1, 1) points at atan2(1, −1) = 135°, while arctan(1/−1) = arctan(−1) = −45° would point the wrong way.

1.3 Vectors and the dot product

A vector (ax, ay) is an arrow in the plane: ax to the right, ay upward. Its length is given by Pythagoras, its direction by atan2:

| a | = √( ax² + ay² )     direction = atan2( ay , ax )

A velocity of 0.3 m/s to the right and 0.4 m/s upward has a speed of √(0.3² + 0.4²) = 0.5 m/s. A unit vector pointing at the angle θ is ( cos θ , sin θ ): it is the “heading” of a robot.

The dot product of two vectors is a number:

a · b = ax bx + ay by = | a | | b | cos( angle between them )

If b is a unit vector, a · b is the component of a along b: the projection. This is the tool behind every wheel equation: the robot has some velocity, and a wheel only cares about the part of it along its plane (that makes it roll) and the part across its plane (that would make it slide).

Worked example

A robot has the velocity (0.6, 0.8) m/s and its wheel points at 30° (unit vector ( 0.866 , 0.5 )). Along the wheel: 0.6 × 0.866 + 0.8 × 0.5 = 0.92 m/s (the wheel rolls at this speed). Across the wheel: the unit vector across is ( −0.5 , 0.866 ), so 0.6 × (−0.5) + 0.8 × 0.866 = 0.39 m/s. A real wheel cannot move sideways: this 0.39 m/s would be slipping. Check: 0.92² + 0.39² = 1.0 = 0.6² + 0.8² ✓.

1.4 Matrices

A matrix is a table of numbers. To multiply a matrix by a vector, take each row, multiply it term by term with the vector, and add:

abcd xy = a x + b yc x + d y

Example: ( 0 1 ; −1 0 ) times (3, 2) gives ( 0×3 + 1×2 , −1×3 + 0×2 ) = (2, −3). Each row of a matrix is a dot product: a matrix is a stack of “projections”. That is how we will write the wheel equations of many wheels at once.

Three facts are enough: the identity matrix I (ones on the diagonal) changes nothing; the inverse A−1 undoes A (A−1A = I) and exists only if the equations of A are independent; the transpose AT swaps rows and columns. The most important matrix of the course is the rotation that turns coordinates by the angle θ:

R(θ) = cos θsin θ− sin θcos θ     R(θ)−1 = R(θ)T = R(−θ)

1.5 Speed, position and integration

Speed is how fast the position changes: v = dx/dt (the derivative). The other way round, position is the sum of all the small displacements: x(t) = ∫ v dt (the integral). A robot only knows its wheel speeds, so it must integrate them to know its position. On a computer, we cut time in steps of Δt and use the Euler method:

xk+1 = xk + vk Δt

Worked example: how the step size matters

A robot accelerates so that v(t) = t (m/s) during 1 s. The exact distance is the area of the triangle: 0.5 m. With Δt = 0.1 s, Euler adds vk Δt for k = 0…9: 0.1 × (0 + 0.1 + … + 0.9) = 0.1 × 4.5 = 0.45 m: 10 % too small. With Δt = 0.01 s the result is 0.495 m. A smaller step gives a better answer, at the price of more computation. A 50 Hz odometry loop (Δt = 0.02 s) is typical.

1.6 Equations and rank

A linear system is a set of equations such as 1 x + 2 y + 0 z = 0. In matrix form A x = b. The rank of A is the number of independent equations: an equation that is a multiple or a sum of the others adds nothing. With n unknowns and rank k, there remain n − k directions that are free: this is the dimension of the null space (the solutions of A x = 0).

Worked example

Unknowns ( ẋ , ẏ , θ̇ ) of a robot. One wheel gives the equation 0 ẋ + 1 ẏ + 0 θ̇ = 0 (no sideways slip). Rank 1, so 3 − 1 = 2 free motions (move along x and turn). A second wheel on the same axle gives −1 times the same equation: the rank stays 1. A second wheel elsewhere gives 0 ẋ + 1 ẏ + 0.5 θ̇ = 0: now the rank is 2, and only 3 − 2 = 1 motion remains. This is exactly how lesson 9 counts the degrees of mobility.

To find the rank by hand, do Gaussian elimination: subtract multiples of the first row from the others to make zeros under the first number, then continue with the next row; the rank is the number of rows that are not all zeros at the end.

What is a wheeled mobile robot? Locomotion, kinematics and dynamics

10 min
You will learn

to say what makes a machine a robot, to name the five subsystems of a wheeled mobile robot, and to know what “kinematics” means for a robot that moves around.

1.1 What is a robot?

There is no precise definition, but by general agreement a robot is a machine with sensing, intelligence and mobility. To qualify, a machine has to be able to:

  1. sense and perceive: get information from its surroundings;
  2. carry out physical tasks: move itself (locomotion) or move objects (manipulation);
  3. be re-programmable: do different things when the program changes;
  4. work autonomously and interact with human beings.

1.2 Families of robots

Robot arms (manipulators) are fixed to the ground; a mobile manipulator is an arm carried by a mobile base. Mobile robots themselves come in several families: wheeled, legged, aerial, underwater and humanoid. This course is about the first family, the wheeled mobile robots (WMR): vacuum robots, warehouse AGV/AMR, planetary rovers, robot cars. They are the simplest mobile robots to build and to control, and they are the most common in factories and homes.

1.3 The five subsystems

A wheeled mobile robot combines hardware and software. It is a collection of subsystems:

SubsystemQuestion it answersExamples
LocomotionHow does the robot move through its environment?wheels, motors, gearboxes, chassis
SensingHow does it measure itself and its surroundings?encoders, gyroscope, lidar, camera
ControlHow does it generate physical actions?speed loops, position control
ReasoningHow does it map measurements to actions?localisation, path planning
CommunicationHow does it talk to other robots or to an operator?Wi-Fi, radio, ROS messages

In the navigation loop of a mobile robot, perception feeds localisation (“where am I?”) and cognition (“where do I go?”); cognition gives a path to motion control, which acts on the real world. This course is the locomotion and motion-control part of that loop.

1.4 Locomotion, dynamics and kinematics

  • Locomotion is the process of causing a robot to move. To produce motion, forces must be applied: motor output, payload, friction.
  • Dynamics studies motion with the forces that cause it: the relation between force and motion.
  • Kinematics studies the mathematics of motion without the forces: the geometric relations between the control parameters (wheel speeds, steering angles) and the behaviour of the robot.

Most mobile-robot controllers work at the kinematic level and ignore the dynamics, as long as the robot moves slowly enough. That is what we do here.

Why it is different from a robot arm

Kinematics of a mobile robot looks like that of an arm, but there is one big difference: an arm is fixed to the ground, so the position of its tool follows directly from the joint angles. A mobile robot moves without bound in its environment. There is no direct way to measure its position: it must be integrated over time from the wheel motions, and every small error is added to the next. This drift of the position estimate is the number 1 challenge of mobile robotics.

Where is the robot? Pose, frames and the rotation matrix

11 min
You will learn

to describe the position and orientation of a robot on the floor with three numbers, and to convert a velocity between the global frame and the frame attached to the robot.

2.1 Three numbers: the pose

On a plane, the robot chassis has three dimensions: two for its position in the plane and one for its orientation around the vertical axis. The posture (or pose) is therefore:

ξI = ( x , y , θ )T    and its velocity    ξ̇I = ( ẋ , ẏ , θ̇ )T

The global frame {XI, YI} is fixed to the floor. The robot frame {XR, YR} is fixed to the chassis, with its origin at the reference point P, and XR pointing forward. The pose is the position of P in the global frame and the angle θ between the two frames.

2.2 From the global frame to the robot frame

The wheels act in the robot frame (“go forward, do not slide sideways”), but we want to know the motion in the global frame. The orthogonal rotation matrix converts one into the other:

R(θ) = cos θsin θ0− sin θcos θ0001     ξ̇R = R(θ) ξ̇I     ξ̇I = R(θ)−1 ξ̇R = R(θ)T ξ̇R

Because R is a rotation matrix, its inverse is simply its transpose. The same matrix will appear in every kinematic model of this course.

Worked example

The robot is rotated by θ = 90° (it points along YI). Then R(π/2) gives ξ̇R = ( ẏ , −ẋ , θ̇ ). A global velocity of ( 1 , 0 , 0 ) m/s along XI becomes ( 0 , −1 , 0 ) in the robot frame: the robot sees the world moving to its right, which is a sideways motion. This is the motion a standard wheel forbids.

With θ = 30° the same global velocity ( 1 , 0 , 0 ) gives ( cos 30° , −sin 30° , 0 ) = ( 0.87 , −0.5 , 0 ) in the robot frame.

2.3 Forward and inverse kinematics of a mobile robot

The goal is to write the speed of the robot as a function of the wheel speeds φ̇i, the steering angles βj and the geometry of the robot (the configuration coordinates):

  • forward kinematics: wheel speeds and steering → robot velocity ξ̇;
  • inverse kinematics: wanted velocity ξ̇ → wheel speeds and steering angles.

Be careful: we can write ξ̇ = f(wheel speeds), but not simply ξ = f(wheel angles). The pose depends on how the wheels were turned over time, not only on how far. We will see the exact reason in lesson 10 (nonholonomic systems).

Wheels and their constraints: rolling and sliding

15 min
You will learn

to know the five wheel types, and to write the two constraints (rolling and no sliding) that each standard wheel imposes on the robot.

3.1 Five wheel types

WheelHow it worksEffect on the robot
Fixed standard wheelFixed to the chassis at an angle; rolls forward and backward; can pivot around its contact point.Constrains the motion: no sideways sliding.
Steered standard wheel (centred orientable)Same, plus a vertical steering axis through the contact point: angle β(t).Constrains the motion; steering changes the constraint over time.

3.2 The assumptions

To get simple equations we model an idealised wheel:

  • the robot moves on a horizontal plane, and the wheel plane stays vertical;
  • the wheel touches the ground at one point and does not deform;
  • pure rolling: the velocity of the contact point is zero;
  • no slipping, skidding or sliding sideways, and no friction against rotation about the contact point;
  • the steering axes are perpendicular to the floor, and the wheels are connected by a rigid chassis.

Under these assumptions each standard wheel gives two constraints: rolling contact (the wheel must roll when the robot moves along its plane) and no lateral slip (the wheel must not slide across its plane).

3.3 The fixed standard wheel

The wheel is attached at a point A, given in polar coordinates by the distance l and the angle α from the reference point P. The angle of the wheel plane with respect to the chassis is β (constant for a fixed wheel). The wheel has radius r and turns at the speed φ̇.

Rolling:   [ sin(α+β)   −cos(α+β)   −l cos β ]   R(θ) ξ̇I − r φ̇ = 0

Sliding:   [ cos(α+β)   sin(α+β)   l sin β ]   R(θ) ξ̇I = 0

The first line says: the speed of the contact point along the wheel plane equals r φ̇ (the wheel really rolls). The second says: the speed across the wheel plane is zero (it does not slide). Each row projects the robot velocity on one direction of the wheel.

Worked example

A wheel is placed at α = 0, β = 0 (on the axis XR, its plane along YR), and the robot has θ = 0. The sliding constraint becomes [ 1 0 0 ] ( ẋ , ẏ , θ̇ )T = 0, that is ẋ = 0: the robot cannot move along X, which is across the wheel. It can still move along Y (rolling) and turn.

3.4 The other wheels

  • Steered wheel. Same two equations, but β = β(t) changes. The steering speed β̇ has no instantaneous effect on the constraints: only by integrating over time does a new steering angle change what the robot can do. Steering alone does not move the chassis.
  • Castor wheel. The rolling equation is the same, but the sliding equation gets two extra terms because of the offset d: [ cos(α+β)   sin(α+β)   d + l sin β ] R(θ) ξ̇I + d β̇ = 0. Any sideways motion can be absorbed by the right steering speed β̇, so the castor wheel imposes no constraint. Here the steering does move the chassis, because of the offset. A five-castor office chair rolls in any direction without sliding.
  • Swedish wheel. Add the roller angle γ: the zero-velocity direction is along the roller axis. Rolling: [ sin(α+β+γ)   −cos(α+β+γ)   −l cos(β+γ) ] R(θ) ξ̇I − r φ̇ cos γ = 0. The rollers turn freely, so the motion along the rollers is not constrained. For γ = 0 (the 90° Swedish wheel) the rollers are perpendicular to the wheel and the robot can slide sideways freely: this is the omni wheel. For γ = 90° the rollers are parallel to the wheel and the wheel behaves like a fixed standard wheel.
  • Spherical wheel. Its equations are those of the fixed standard wheel, but the angle β is a free variable instead of a constant: no constraint remains.
The key result

Castor, Swedish and spherical wheels put no kinematic constraint on the chassis: the robot velocity can take any value because of the internal degrees of freedom of these wheels. Only fixed and steered standard wheels constrain the chassis, so only they matter when we compute how a robot can move (lessons 9 and 10).

Differential drive: the simplest mobile robot

to compute how a two-wheel differential robot moves from its wheel speeds, and the opposite: which wheel speeds give the motion you want.

4.1 The robot

A differential-drive robot has two driven fixed wheels on the same axle, a distance L apart, each with its own motor, and usually a castor wheel or a ball for balance. It is the simplest drive mechanism and the one of most vacuum robots and educational robots. The control input is not the speed of each wheel but the motion of the robot itself:

U = ( v , ω )T    v = linear speed of the robot (m/s)    ω = angular speed (rad/s)

4.2 Wheel speeds ↔ robot motion

A wheel of radius r turning at φ̇ has a ground speed V = r φ̇. The left and right wheels turn about the same point at the same angular rate ω, so:

VR = r φ̇R    VL = r φ̇L      v = ( VR + VL ) / 2      ω = ( VR − VL ) / L

Inverse:   VR = v + ω L / 2     VL = v − ω L / 2

The speed of the robot is the average of the two wheel speeds, and its rotation is their difference divided by the distance between the wheels. If you drive the right wheel faster, the robot turns left (counterclockwise).

4.3 The turning circle and the ICC

At every instant both wheels follow circles around one point, the instantaneous centre of curvature (ICC, also called ICR). It lies on the axle line, at the distance R from the middle of the axle:

4.6 Odometry: computing the pose from the wheels

With encoders, each wheel gives the distance ΔsR and ΔsL it has rolled in one time step. Then:

Δs = ( ΔsR + ΔsL ) / 2    Δθ = ( ΔsR − ΔsL ) / L    x ← x + Δs cos( θ + Δθ/2 )   y ← y + Δs sin( θ + Δθ/2 )   θ ← θ + Δθ

Pitfall: small errors, big drift

The trajectory is very sensitive to the relative speed of the two wheels, not only to their average. A wheel diameter wrong by 1 % makes the robot curve instead of going straight, and odometry accumulates this error without limit. This is why real robots add a gyroscope, a lidar or a camera to correct the pose (see the “Perception” course).

Tricycle, bicycle and car: steering and the Ackermann rule

18 min
You will learn

to compute the wheel speeds and steering angles of a bicycle and of a car from the speed and the steering angle, and to explain why the two front wheels of a car do not turn by the same angle.

5.1 The tricycle

A tricycle has two fixed rear wheels and one front wheel that steers and drives, at the distance d in front of the rear axle. The inputs are the steering angle α(t) and the speed vs of the front wheel. All the wheel axes must meet at one point, so the ICC lies on the rear axle line, and the robot turns around it on a circle of radius:

R = d / tan α     v = vs cos α     ω = ( vs / d ) sin α

ẋẏθ̇ = cos θ0sin θ001 vs cos α(vs / d) sin α

The tricycle has a limited radius of curvature (it cannot spin on the spot) and cannot steer by ±90°. But it is simple and stable at speed.

5.2 Exercise: the bicycle

Question. A bicycle has a rear wheel (radius rF) and a front steering wheel (radius rC), a distance e apart. Knowing the speed v of the front wheel (along its direction) and the steering angle δ, find the angular velocities φ̇F of the rear wheel and φ̇C of the front wheel.

Solution. The front wheel rolls without slipping: its contact point moves at v along the wheel, so φ̇C = v / rC. The two wheels are on a rigid frame, so their velocity components along the line that joins them are equal. The rear wheel moves along the frame at vr, the front wheel has the component v cos δ along it. Hence vr = v cos δ, and φ̇F = v cos δ / rF.

φ̇C = v / rC     φ̇F = v cos δ / rF     ( ω = v sin δ / e ,   R = e / tan δ )

Worked example

rF = rC = 0.35 m, e = 1.1 m, v = 3 m/s, δ = 20°. Then φ̇C = 3 / 0.35 = 8.57 rad/s and φ̇F = 3 cos 20° / 0.35 = 8.05 rad/s: the rear wheel turns slower than the front one in a turn. The bicycle turns at ω = 3 sin 20° / 1.1 = 0.93 rad/s, around a point at R = 1.1 / tan 20° = 3.02 m from the rear wheel. If δ = 0 the two speeds are equal.

5.3 Exercise: the car

Question. Now a car with two rear wheels F1, F2 (track L) and two steering front wheels C1, C2 (wheelbase e). Knowing v and the steering angle δ of the “virtual” central wheel, find the four wheel speeds φ̇F1, φ̇F2, φ̇C1, φ̇C2 and the two steering angles δC1, δC2.

Solution. Replace the car by its “bicycle” in the middle: it gives the ICC on the rear axle line, at R = e / tan δ from the middle of the rear axle, and the rotation ω = v sin δ / e. Every wheel is then a point that turns around the ICC at the same ω: its speed is ω times its distance to the ICC, and its plane is perpendicular to the line to the ICC. For a left turn, wheel 1 (left) is on the inside:

φ̇F1 = ω ( R − L/2 ) / rF1    φ̇F2 = ω ( R + L/2 ) / rF2

tan δC1 = e / ( R − L/2 )    tan δC2 = e / ( R + L/2 )    φ̇Ci = ω √( e² + ( R ∓ L/2 )² ) / rCi

Worked example

e = 2.5 m, L = 1.4 m, all radii 0.30 m, v = 5 m/s, δ = 15°. Then R = 2.5 / tan 15° = 9.33 m and ω = 5 sin 15° / 2.5 = 0.518 rad/s. Steering angles: δC1 = 16.2° (inside), δC2 = 14.0° (outside). Wheel speeds: φ̇F1 = 14.9, φ̇F2 = 17.3, φ̇C1 = 15.5, φ̇C2 = 17.8 rad/s. The outside wheels turn faster because they travel on a bigger circle: this is what the differential gear of a car allows.

5.4 The Ackermann rule

In a car the inside front wheel is turned slightly more than the outside one. This is not a detail: the axes of the four wheels must meet at the single ICC, otherwise the tyres drag sideways, wear and slip. With the track d (= L) and the wheelbase l (= e), this gives the Ackermann equation, where the angles are measured from the straight-ahead direction:

cot δoutside − cot δinside = d / l     cot δ = ( cot δinside + cot δoutside ) / 2

Check with the example: cot 14.0° − cot 16.2° = 4.01 − 3.45 = 0.56 = 1.4 / 2.5. ✓ The mean cotangent is that of the central “virtual” wheel δ = 15°. Ackermann steering gives a fairly accurate dead-reckoning solution and supports traction and ground clearance, which is why it is the usual choice for outdoor autonomous vehicles.

What a car cannot do

A car has only 2 control inputs (speed and steering) for 3 pose numbers, and its steering angle is limited, so it needs a series of manoeuvres to park sideways. Lesson 7 will count exactly how much freedom it has.

Omnidirectional robots and synchro drive

6.1 Why omnidirectional?

A robot with fixed standard wheels cannot move sideways. A robot with Swedish (omni) wheels can: each wheel drives along its own plane and rolls freely across it on the small rollers. With three such wheels, any combination of forward speed, sideways speed and rotation can be commanded at once: the robot is holonomic with 3 independent velocities. Soccer robots, warehouse platforms and stage robots use this. The price is a complex structure, weak frames (small rollers), slipping on dust, and bumpy motion on rough floors.

6.2 Three Swedish 90° wheels

Place three identical Swedish 90° wheels at the distance l from the centre P, at the angles α1 = 60°, α2 = 180°, α3 = −60°, with β = 0 (wheels tangent to the body) and γ = 0. There is no sliding constraint, so only the three rolling constraints remain. Each row of the matrix J1 is the rolling row of lesson 4:

Worked example

The robot moves and turns at the same time, with all the three speeds computed from the three wheels. If all three wheels run at the same speed, ẋ = ẏ = 0 and the robot spins on the spot.

This is the general method of the course: write the rolling and sliding constraint of every wheel, stack them, and solve. Four Mecanum wheels in an “X” layout work the same way, with the wheel rollers at ±45°: see the wheels page to drive one.

6.3 Synchro drive

In a synchro drive, each of three wheels (at the corners of an equilateral triangle, often under a cylindrical body) is both driven and steered, but a system of belts links them so that all the wheels point in the same direction and turn at the same rate. One motor drives all the wheels, one motor steers them all. So the robot has exactly two independent inputs: the speed v and the direction of travel.

  • All wheels stay parallel, so the ICC is always at infinity: the robot translates, it never moves on a curve by itself. Turning the wheels changes the direction of the ICC.
  • v = 0 with the wheels turning: the wheels rotate in place. ω = 0 with v ≠ 0: the robot goes straight in the direction its wheels point.
  • The body of the robot does not turn when the wheels are steered. To keep sensors facing the travel direction, a third motor and a turret are needed. This is a classic design for research robots with a cylindrical body.

Compared with a differential robot, a synchro drive can change its direction of travel without turning its body, and the belts keep all the wheels locked together. But it is mechanically complex, and lesson 9 will show that it has only 2 degrees of maneuverability: it cannot rotate its body without the turret.

Worked example

Then k ω = 0.07 and φ̇FL = (0.5 − 0.3 − 0.07) / 0.05 = 2.6, φ̇FR = (0.5 + 0.3 + 0.07) / 0.05 = 17.4, φ̇RL = (0.5 + 0.3 − 0.07) / 0.05 = 14.6, φ̇RR = (0.5 − 0.3 + 0.07) / 0.05 = 5.4 rad/s. Checking with the forward formulas gives back (0.5, 0.3, 0.2). For a pure sideways motion (vy only) the wheels run in the pattern −, +, +, −: the two diagonals turn in opposite directions.

Four wheels, three unknowns: a hidden condition

The robot has 3 degrees of freedom but 4 wheels, so the four wheel speeds cannot be chosen freely. They must satisfy φ̇FL + φ̇FR = φ̇RL + φ̇RR (check with the example: 2.6 + 17.4 = 14.6 + 5.4 = 20). If a wheel leaves the floor, or if the floor is uneven, this condition is broken and a wheel slips. This is why Mecanum robots need a suspension that keeps the four wheels on the ground.

In practice: a Mecanum robot is fully holonomic (δm = 3) and easy to program, but its rollers slip a little, so the odometry is less accurate than for a differential robot, the wheels have less grip, and sideways motion needs more motor effort than forward motion (the rollers split the force).

8.2 Swerve drive

A swerve robot has several modules, each one a standard wheel that can be both steered and driven by its own motors. Like the Mecanum robot it can produce any motion, but with the grip and the efficiency of normal wheels, which is why it is used in competition robots and in some heavy AMRs. At rest, the position of the module i is ( xi , yi ). For the robot velocity ( vx , vy , ω ), the velocity of the point where this module touches the floor is the robot velocity plus the rotation:

ux = vx − ω yi    uy = vy + ω xi    speed = √( ux² + uy² )    steering angle = atan2( uy , ux )

Worked example

Four modules at ( ±0.30 , ±0.25 ) m. The robot goes forward at 0.5 m/s while it turns at 1 rad/s. Front-left module ( 0.30 , 0.25 ): u = ( 0.5 − 1 × 0.25 , 0 + 1 × 0.30 ) = ( 0.25 , 0.30 ), so speed 0.39 m/s at 50.2°. Front-right ( 0.30 , −0.25 ): u = ( 0.75 , 0.30 ), speed 0.81 m/s at 21.8°. By symmetry the rear modules have the opposite angles (−50.2° and −21.8°). Every module has a different speed and angle: the robot is turning around a point that is not at its centre.

Two details that professionals never forget: (1) Never steer more than 90°. If a module must go from 10° to 170°, it is faster to rotate it by −10° and to reverse the drive direction (steering angle 170° − 180° = −10°, speed × −1). (2) Never rotate a module faster than its steering motor allows: a swerve robot must slow down while the modules are not yet aligned with their targets.

8.3 When a motor saturates: scale, do not clip

Every motor has a maximum speed. If one wheel command is above it, you must scale all the wheels by the same factor, not just limit the one wheel: otherwise the ratio between the wheels changes and the robot goes in another direction. For each drive: s = max( 1 , max |φ̇i| / φ̇max ) and the commands become φ̇i / s.

Worked example

Four commands ( 18 , 22 , 26 , 10 ) rad/s with a limit of 20 rad/s. The largest is 26, so s = 26 / 20 = 1.3 and the commands become ( 13.8 , 16.9 , 20 , 7.7 ). The robot moves in the wanted direction but 1.3 times slower. If you had clipped only 26 to 20, the wheel ratios would change and the robot would drift sideways.

8.4 Skid-steer and tracked robots

A skid-steer robot (four wheels or two tracks, driven left and right like a differential robot) has no true rolling-only motion when it turns: the wheels on one side are not aligned with the circle, so they must slip sideways. The “ideal” differential model ω = ( VR − VL ) / L then over-predicts the turning rate. A simple, widely used correction is an effective track Leff = χ L, with a factor χ > 1 that depends on the ground and on the robot and that you measure (lab 3):

ω = ( VR − VL ) / ( χ L )     χ = ( VR − VL ) / ( L ωmeasured )

Worked example

A tracked robot has L = 0.40 m. Spinning on the spot with VR = 0.30 m/s and VL = −0.30 m/s, the ideal model predicts ω = 0.60 / 0.40 = 1.5 rad/s. A gyroscope measures 0.75 rad/s. Then χ = 0.60 / (0.40 × 0.75) = 2.0: the effective track is 0.80 m. Using the corrected model, the heading error after a 90° turn drops from a factor 2 to a few percent. In real projects, the gyroscope is preferred for the heading, and this χ only helps predict it.

Maneuverability: how freely can a robot move?

17 min
You will learn

to stack the constraints of all the wheels, to find the instantaneous centre of rotation (ICR) from them, and to compute the degrees of mobility, steerability and maneuverability of any wheel layout.

7.1 Stacking the constraints

Take a robot with Nf fixed and Ns steered standard wheels (the only ones that constrain the chassis, lesson 4). Put their rolling and sliding rows one under the other:

Rolling:   J1(βs) R(θ) ξ̇I − J2 φ̇ = 0     Sliding:   C1(βs) R(θ) ξ̇I = 0

J1 and C1 have one row per standard wheel (Nf + Ns rows) and 3 columns; J2 = diag(r1 … rN) holds the wheel radii; φ̇ is the vector of the wheel speeds. The sliding equation is the important one for what the robot can do: the velocity R(θ) ξ̇I must lie in the null space of C1, the set of the vectors n such that C1 n = 0.

7.2 The ICR: a picture of the null space

Geometrically, each standard wheel forbids the motion along its axle. At every instant the wheel must move along a circle whose centre is on the zero-motion line (the line along its axle, perpendicular to its plane). The point where all the zero-motion lines meet is the instantaneous centre of rotation (ICR): the robot turns around it.

  • Bicycle: the rear wheel and the steered front wheel each give one line; they meet at one point.
  • Differential drive: both wheels share the same axle line, so they give the same line: the ICR can be anywhere along it.
  • Car: four wheels but only one ICR; the second steered wheel adds no new constraint (it must simply point to the same ICR, Ackermann rule).
Mobility depends on independent constraints, not on the number of wheels

A bicycle and a differential robot both have two non-omnidirectional wheels, but the bicycle has two independent constraints and the differential robot only one, because the second wheel has the same zero-motion line as the first. The number of independent constraints is the rank of C1(βs): the higher the rank, the more constrained the robot.

7.3 The three degrees

Three wheels are enough for a robot to stand stable on its own; extra wheels must be synchronised (or suspended). The largest numbers of δM come from omni wheels (no constraint) and from independent steered wheels. Two robots with the same δM are not equivalent. The differential drive and the tricycle both have δM = 2, but the first has (2, 0): all its freedom is immediate, while the second has (1, 1): half of it comes from steering and takes time. Worked example: the rank of a differential robot and of a locked bicycle

Differential drive: both wheels have the row [ cos α1   sin α1   0 ] and its negative: the two rows are proportional, so rank C1 = 1 and δm = 3 − 1 = 2. Locked bicycle (steering fixed straight): the rows [ 0   1   l1 ] and [ 0   −1   l1 ] are independent, so rank = 2 and δm = 1: the robot can only move along a curve (or a line).

Holonomic or not? Degrees of freedom, paths and trajectories

14 min
You will learn

to explain what “nonholonomic” means, why a car cannot go sideways but can still park, and what the difference is between a path and a trajectory.

8.1 DOF, DDOF and maneuverability

Maneuverability δM counts the degrees of freedom we can control. We also ask: what poses can the robot reach in its workspace, and how?

  • DOF (degrees of freedom of the workspace): the poses the robot can reach. For a mobile robot on a floor we want DOF = 3 ( x, y, θ ).
  • DDOF (differential degrees of freedom): the velocities the robot can produce independently at one instant, which is the degree of mobility δm. It tells which paths are possible.

DDOF ≤ δM ≤ DOF

A bicycle has DOF = 3 (it can end at any pose) but DDOF = 1 (at each instant it can only drive forward or backward along its heading). An omnidirectional robot has DOF = 3 and DDOF = 3. Both reach every pose, but the omnidirectional robot reaches it directly, and the bicycle needs a sequence of manoeuvres like parallel parking.

8.2 Holonomic and nonholonomic constraints

A holonomic kinematic constraint can be written as a function of the position variables only (x, y, θ, wheel angles…). A nonholonomic constraint needs derivatives (velocities) and cannot be integrated to remove them. Such systems are also called nonintegrable. A robot is holonomic if and only if DDOF = DOF.

  • The sliding constraint of a fixed or steered standard wheel, ẋ sin θ − ẏ cos θ = 0 for a differential robot, uses the velocity: it is nonholonomic.
  • Differential drive, tricycle, car, two-steer: nonholonomic (DDOF < DOF = 3).
  • Omnidirectional robot: no constraint at all, holonomic with DDOF = 3.
  • Locked bicycle (steering blocked): all constraints can be integrated into constraints on the pose, it can only move on a curve: holonomic, but of no interest (DOF = 1).

8.3 Proof that a mobile robot is nonholonomic

Take a robot that moves along a trajectory s(t). In a short time the distance travelled is ds = dx cos θ + dy sin θ. This could be integrated into a function s(x, y, θ) of the pose alone only if the second derivatives of s do not depend on the order of derivation:

∂²s / ∂x∂θ = ∂²s / ∂θ∂x    etc.

Here ∂s/∂x = cos θ, ∂s/∂y = sin θ and ∂s/∂θ = 0. Then ∂/∂θ(∂s/∂x) = −sin θ, but ∂/∂x(∂s/∂θ) = 0: they are different, so no such function exists. In words: the distance travelled by each wheel is not enough to know where the robot is. Two robots can roll the same distances with their wheels, but ending in different places, because they did it in a different order. We must also know how the motion was done, as a function of time. This is why odometry integrates the speeds step by step, and why the pose is not a function of the wheel angles.

8.4 Path versus trajectory

A path is a curve in pose space (x, y, θ): 3 dimensions. A trajectory adds time: (x, y, θ, t), 4 dimensions. The two kinds of robots with δM = 3 differ here:

  • The omnidirectional robot controls all 3 velocities directly (δm = 3): it can follow any trajectory, at any speed along it. But it is not stable at high speed (centripetal forces on wheels that do not resist sideways), and it needs ground clearance and suspension for its special wheels.
  • The two-steer robot (δm = 1, δs = 2) can choose any ICR, so it can follow any path. But changing the steering takes time, so arbitrary trajectories are not possible.
  • A car-like robot with nonholonomic constraints is more stable: the sideways centripetal force in a turn is passively counteracted by the sliding constraints of its wheels. This is one reason why cars and fast outdoor robots are nonholonomic on purpose.

Motion control: driving a robot to a goal pose

18 min
You will learn

to compare open-loop and feedback control for a mobile robot, to write the polar-coordinate control law of a differential robot, and to choose gains that make it converge.

9.1 The goal of kinematic control

A kinematic controller makes the robot follow a trajectory described by position and/or velocity profiles as functions of time. It is not straightforward, because mobile robots are nonholonomic: you cannot just move to the right. Still, several good solutions exist. Most of them ignore the dynamics of the system and give the speeds that the wheels must have (lesson 5).

9.2 Open-loop control

Divide the path into segments of clearly defined shapes, straight lines and circle arcs, and pre-compute the speeds of each. The disadvantages:

  • it is not easy to pre-compute a feasible trajectory;
  • it must respect the limits of the robot velocities and accelerations;
  • it does not correct errors, or adapt if the environment changes;
  • the resulting trajectories are usually not smooth (the curvature jumps between a line and a circle).

9.3 Feedback control: the problem

With feedback, the controller uses the error e between the current pose and the goal: we look for a matrix K (2×3, its elements may depend on time and on the error), such that the commands

( v , ω )T = K · e = K · ( x , y , θ )T    drive the error to zero:   limt→∞ e(t) = 0

Because the robot is nonholonomic, a constant matrix K cannot do it: the gains must depend on the error (kij = k(t, e)). A convenient way to get such gains is to change the coordinates.

9.4 Polar coordinates of the goal

Put the origin of a frame at the goal and describe the robot by three polar quantities, where Δx, Δy is the vector from the robot to the goal:

ρ = √( Δx² + Δy² )    α = −θ + atan2( Δy , Δx )    β = −θ − α    (goal angle θg = 0)

  • ρ: the distance to the goal;
  • α: the angle between the robot heading and the direction of the goal (“am I pointing at it?”);
  • β: the angle between the line of sight and the goal orientation (“am I arriving the right way?”).

With the kinematics of the differential robot (ẋ = v cos θ, ẏ = v sin θ, θ̇ = ω), the system becomes, for α in (−90°, 90°]:

ρ̇ = −v cos α     α̇ = ( v sin α ) / ρ − ω     β̇ = −( v sin α ) / ρ

For α outside this range the robot has the goal behind it: the same equations hold with the robot's “front” redefined as its back, and v changes sign: the robot drives backwards and arrives with its back to the goal direction (θ ≈ 180° instead of 0). Note also that the transformation is not defined at ρ = 0 (the goal itself), where the angles have no meaning.

9.5 The control law

v = kρ ρ     ω = kα α + kβ β

It is a proportional law: go faster when far from the goal, turn toward the goal with kα, and turn to arrive in the right orientation with kβ. Closed loop, the system is:

ρ̇ = −kρ ρ cos α     α̇ = kρ sin α − kα α − kβ β     β̇ = −kρ sin α

Stability: how to choose the gains

For small α, sin α ≈ α and cos α ≈ 1, and the system is linear. Its characteristic polynomial is ( λ + kρ ) ( λ² + λ ( kα − kρ ) − kρ kβ ). All its roots have a negative real part, so the robot converges to ( ρ, α, β ) = ( 0, 0, 0 ), if:

kρ > 0     kβ < 0     kα − kρ > 0

A textbook choice is kρ = 3, kα = 8, kβ = −1.5. Note that ρ then shrinks faster than the angles converge, so the final heading is a little off when you stop at a distance tolerance: a smaller kρ (about 1 to 1.5) and a larger |kβ| give a more precise heading, but a slower approach. Another nice property: the speed v keeps a constant sign, so the robot never reverses during its approach: it parks in the most natural way.

Finally the commands v and ω are converted into wheel speeds with VR = v + ω L/2 and VL = v − ω L/2 (lesson 5), and the motors' own speed loops (lesson “Dynamics and control”) follow them. In practice, add saturations on v and on the wheel speeds, and stop when ρ is below a tolerance, since the law has no meaning at the goal itself.

Following a path: pure pursuit, Stanley and trajectory tracking

18 min
You will learn

to make a robot follow a path (not only reach a point), with the three standard controllers, and to choose their parameters with the speed and the delay of the robot.

12.1 From “go to a point” to “follow a path”

Lesson 11 drove the robot to one goal pose. A real robot has to follow a whole path: a list of points given by a planner, a line painted on the floor, or the lane of a road. The quality of the tracking is measured by two errors:

  • the cross-track error ey: the distance from the robot to the nearest point of the path;
  • the heading error eθ: the angle between the robot heading and the tangent of the path.

12.2 Pure pursuit

The idea is the one of a driver looking ahead on the road. At each step: (1) find the point of the path nearest to the robot; (2) walk along the path until you are at the look-ahead distance Ld from the robot: this is the target; (3) steer along the circle that goes from the robot to the target while being tangent to the robot heading.

Express the target in the robot frame: ( xg , yg ), with x forward and y to the left, and Ld² = xg² + yg². The circle through the robot (tangent to its heading) and the target has the curvature:

κ = 2 yg / Ld²     R = 1 / κ     differential robot: ω = v κ     car: δ = arctan( e κ )

Why 2 yg / Ld²? A circle tangent to the x axis at the origin has its centre at (0, R). The target is on it: xg² + ( yg − R )² = R², which gives xg² + yg² = 2 R yg, so R = Ld² / (2 yg).

Worked example

A differential robot (L = 0.4 m) goes at v = 0.5 m/s. The target is at ( 1.0 , 0.3 ) m in its frame. Then Ld² = 1.09, κ = 0.6 / 1.09 = 0.55 1/m (R = 1.82 m) and ω = 0.5 × 0.55 = 0.275 rad/s; the wheels run at VR = 0.5 + 0.275 × 0.2 = 0.555 m/s and VL = 0.445 m/s. A car (e = 2.5 m) with a target at ( 5 , 0.6 ): κ = 1.2 / 25.36 = 0.0473 1/m, so δ = arctan( 2.5 × 0.0473 ) = 6.7°.

12.3 Choosing the look-ahead distance

Ld is the only real parameter, and it is a compromise:

  • too small: the robot reacts hard to every small error; with the delay of the motors and of the computer it oscillates around the path, and can even become unstable;
  • too large: the robot cuts the corners of the path and is slow to come back after a disturbance.

The right Ld grows with the speed: the faster the robot, the farther it must look. A usual rule is Ld = L0 + k v, with k between 0.5 and 2 seconds. Try it below: with no motor lag any small Ld works, but add a lag of 0.4 s and a high speed, and a small Ld makes the robot unstable.

12.4 Stanley: the controller of the front axle

For a car, the Stanford team (DARPA Grand Challenge, 2005) used a controller that measures the errors at the front axle and steers by the sum of two terms: the heading error, and a correction of the cross-track error that gets weaker when the speed grows:

δ = eθ + arctan( k ey / v )    (then limit δ to the steering range of the car)

Worked example

eθ = 0.1 rad, ey = 0.5 m, k = 1, v = 2 m/s: δ = 0.1 + arctan( 1 × 0.5 / 2 ) = 0.1 + 0.245 = 0.345 rad = 19.8°. At v = 8 m/s the same errors give 0.1 + arctan(0.0625) = 0.162 rad = 9.3°: the controller steers less when it goes fast, so it does not oscillate.

12.5 Tracking a trajectory (position and time)

If the path comes with a schedule (a trajectory: a reference pose ( xr , yr , θr ) and the speeds vr, ωr at every time), the robot must also be at the right place at the right time. Write the error in the robot frame: ( ex , ey , eθ ) = R(θ) ( pr − p ). The classical law of Kanayama (1990) for the unicycle is:

v = vr cos eθ + kx ex     ω = ωr + vr ( ky ey + kθ sin eθ )     kx, ky, kθ > 0

Each term has a clear role: the first parts are the feed-forward (the speeds the reference would need: vr, ωr) and the others are the feedback that corrects the errors. A good tracker always has both: feed-forward alone drifts, feedback alone is late.

Worked example

vr = 0.5 m/s, ωr = 0.2 rad/s. Error: ex = 0.10 m (the robot is behind), ey = 0.05 m, eθ = 0.1 rad. Gains kx = 1, ky = 5, kθ = 2. Then v = 0.5 cos 0.1 + 1 × 0.10 = 0.598 m/s (faster than the reference to catch up) and ω = 0.2 + 0.5 ( 5 × 0.05 + 2 sin 0.1 ) = 0.2 + 0.5 × 0.450 = 0.425 rad/s.

12.6 Practical limits every controller needs

  • Slow down in curves. The lateral acceleration is v² κ. If you allow at most alat, then v ≤ √( alat / | κ | ). With alat = 1 m/s² and a turn of radius 2 m (κ = 0.5): v ≤ 1.41 m/s.
  • Respect the wheel limit. In a turn the outer wheel goes faster: VR = v ( 1 + κ L / 2 ). If a wheel can do 1.2 m/s, κ = 1 and L = 0.5 m, then v ≤ 1.2 / 1.25 = 0.96 m/s.
  • Compensate the delay. If the command arrives 0.2 s late, at 1 m/s the robot has moved 0.2 m. Estimate the pose forward in time by the delay before computing the errors, or increase Ld.
  • Measure. Report the RMS and the maximum of the cross-track error, never only “it looks good” (lesson 18).

Planning paths for nonholonomic robots: Dubins, parking and speed profiles

18 min
You will learn

to find the shortest feasible path of a car-like robot between two poses, to see why curvature and smoothness matter, and to compute the speed profile along a path.

13.1 A straight line is not always a path

A holonomic robot can follow any curve: the shortest path between two poses is a line, then a rotation. A nonholonomic robot cannot. A car has a minimum turning radius Rmin = e / tan δmax (lesson 6), so the curvature of every feasible path satisfies:

| κ | ≤ 1 / Rmin

The curvature of a plane curve ( x(s) , y(s) ) is κ = ( x′ y″ − y′ x″ ) / ( x′² + y′² )3/2. A planner for such robots must output paths whose curvature never exceeds this limit: a path that a robot cannot drive is useless. (A differential robot can turn on the spot, so for it Rmin = 0, but sharp corners still force it to stop and turn.)

13.2 Dubins paths

In 1957 Dubins proved a beautiful result: for a robot that only goes forward with a minimum turning radius R, the shortest path between two poses is always made of at most three pieces, each one a left arc (L), a right arc (R) or a straight line (S). Only six words are possible: LSL, RSR, LSR, RSL, RLR and LRL. The four with a straight line (“CSC” paths) are given by simple formulas. Place the start at the origin pointing along x, and put the goal at distance d = (distance between the poses) / R in the direction θ. With α = −θ and β = θgoal − θ (all angles mod 2π), the lengths, in units of R, of the first arc t, the line p and the last arc q are, for example:

LSL:   p² = 2 + d² − 2 cos(α−β) + 2d ( sin α − sin β )   tmp = atan2( cos β − cos α , d + sin α − sin β )   t = −α + tmp   q = β − tmp

The other three words have similar formulas (the widget below computes all four and picks the shortest). The total length is R ( t + p + q ). We checked these formulas numerically: following the three pieces ends exactly on the goal pose.

Worked example

Start (0, 0, 0°), goal ( 3 , 2 , 90° ), R = 1 m. The four straight-line words give lengths: LSL 3.81 m, LSR 9.82 m, RSL 10.06 m, RSR 16.00 m. The shortest is LSL: turn left, drive straight, then turn left again. The straight line distance is only 3.6 m, but the robot needs 3.81 m because it must also arrive with the right heading. If the goal is straight ahead at ( 4 , 0 , 0° ) the path degenerates to a line of 4 m.

13.3 Reversing: Reeds–Shepp and parking

A real car can also reverse. Reeds and Shepp (1990) solved the same problem when going backwards is allowed: the shortest path then has up to five pieces (arcs, lines, and cusps where the car stops and changes direction), in 46 possible words. You do not code this by hand: planners such as the Smac Hybrid-A* planner of Nav2 or OMPL provide Dubins and Reeds–Shepp paths as building blocks. What you must know is what the result means: parallel parking is a short Reeds–Shepp path, with two arcs in reverse, and its feasibility depends on the minimum turning radius and on the length of the free space.

13.4 Smooth paths and differential flatness

A Dubins path jumps from curvature 0 (a line) to 1/R (an arc) at once: a real car would have to turn its steering wheel instantly. To avoid this, planners use curves whose curvature changes smoothly: clothoids (curvature growing linearly with the distance, κ(s) = κ0 + c s), splines or Bézier curves.

A deep and very practical fact: the unicycle (and the differential robot) is differentially flat. Its pose and its commands can be computed from the path x(t), y(t) and its derivatives, without integrating anything:

θ = atan2( ẏ , ẋ )    v = √( ẋ² + ẏ² )    ω = ( ẋ ÿ − ẏ ẍ ) / ( ẋ² + ẏ² ) = κ v

Example: a circle of radius 2 m driven at 0.5 m/s has κ = 0.5 1/m, so the feed-forward command is ω = κ v = 0.25 rad/s, constant.

13.5 The speed profile along the path

The path says where; the speed profile says when. The simplest profile accelerates at a up to vmax, cruises, then brakes at a (a trapezoid in the speed–time graph). For a distance s:

  • if s ≥ vmax² / a (the robot has the time to reach vmax): total time T = s / vmax + vmax / a;
  • otherwise the profile is a triangle: peak speed vpeak = √( a s ), total time T = 2 √( s / a ).
Worked example

a = 0.5 m/s², vmax = 1 m/s. For s = 5 m: v²/a = 2 m ≤ 5 m, so T = 5 / 1 + 1 / 0.5 = 7 s. For s = 0.8 m: 0.8 < 2 m, triangle: vpeak = √( 0.5 × 0.8 ) = 0.63 m/s and T = 2 √( 0.8 / 0.5 ) = 2.53 s.

Along a curved path, take the minimum of all the limits at each point: v ≤ vmax, v ≤ √( alat / | κ | ), v ≤ Vwheel,max / ( 1 + | κ | L / 2 ), and the braking limit before an obstacle or a stop (lesson 18). Then smooth the accelerations. Professional profiles also limit the jerk (the change of acceleration, the “S-curve”), which protects the load and the gearboxes.

Odometry in practice: encoders, errors and calibration

You will learn

to turn encoder counts into distances, to understand the sources of odometry error, to calibrate the wheel radii and the track width with simple tests, and to know what a gyroscope adds.

14.1 From encoder counts to metres

A wheel encoder gives counts. A quadrature encoder with N lines per turn (“CPR”) gives 4 N counts per turn of the motor shaft, because the two channels A and B give four edges per line (and the order of the edges gives the direction). If the gearbox has the ratio G (motor turns per wheel turn), then:

counts per wheel turn = 4 N G     distance per count = 2π r / ( 4 N G )     Δs = ( countsnow − countsbefore ) × distance per count

Worked example

N = 500 lines, G = 30, r = 0.05 m. Counts per wheel turn: 4 × 500 × 30 = 60 000. Distance per count: 2π × 0.05 / 60 000 = 5.2 µm. At 1 m/s the robot makes 191 000 counts per second: too fast to read with a normal software interrupt, so use the hardware encoder counter of the microcontroller. At 100 Hz sampling one step is about 1 910 counts, so the speed resolution (one count per step) is 0.0005 m/s: excellent. Compare a cheap encoder of 20 counts per wheel turn: 15.7 mm per count and, at 100 Hz, a speed resolution of 1.57 m/s, which is useless. Then you must measure the time between counts, or use a longer window.

14.2 The odometry update, and its code

Each cycle, read the two distances ΔsR and ΔsL and update the pose with the midpoint rule of lesson 5: Δs = ( ΔsR + ΔsL ) / 2, Δθ = ( ΔsR − ΔsL ) / L, x += Δs cos( θ + Δθ/2 ), y += Δs sin( θ + Δθ/2 ), θ += Δθ. Here is a complete program, with a simulator of a robot whose real wheels are not the nominal ones. Run it (python3 odometry.py):

import math, random

class Odometry:
    """Differential-drive dead reckoning from the distance rolled by each wheel."""
    def __init__(self, track, x=0.0, y=0.0, th=0.0):
        self.L, self.x, self.y, self.th = track, x, y, th

    def update(self, ds_right, ds_left):
        ds = 0.5 * (ds_right + ds_left)            # distance of the robot centre
        dth = (ds_right - ds_left) / self.L        # change of heading
        self.x += ds * math.cos(self.th + 0.5 * dth)   # midpoint rule
        self.y += ds * math.sin(self.th + 0.5 * dth)
        self.th += dth
        return self.x, self.y, self.th

def drive_square(side, v, w, true_r_scale=(1.0, 1.0), true_track_scale=1.0, noise=0.0, dt=0.01, ccw=True, seed=1):
    """Open-loop square. The commands are computed with the NOMINAL robot (r = 0.05, L = 0.30),
    the robot really moves with the TRUE parameters. Returns the real final pose."""
    random.seed(seed)
    r, L = 0.05, 0.30
    rr, rl = r * true_r_scale[0], r * true_r_scale[1]; Lt = L * true_track_scale
    x = y = th = 0.0
    sgn = 1 if ccw else -1
    def run(vv, ww, T):
        nonlocal x, y, th
        n = int(round(T / dt))
        for _ in range(n):
            wr = (vv + ww * L / 2) / r; wl = (vv - ww * L / 2) / r            # commanded wheel speeds (rad/s)
            dsr = rr * wr * dt * (1 + random.gauss(0, noise)); dsl = rl * wl * dt * (1 + random.gauss(0, noise))
            ds = 0.5 * (dsr + dsl); dth = (dsr - dsl) / Lt
            x += ds * math.cos(th + 0.5 * dth); y += ds * math.sin(th + 0.5 * dth); th += dth
    for _ in range(4):
        run(v, 0.0, side / v)
        run(0.0, sgn * w, (math.pi / 2) / w)
    return x, y, th

if __name__ == "__main__":
    # 1. perfect robot: the 2 m square closes
    x, y, th = drive_square(2.0, 0.4, 1.0)
    print("perfect robot     : end (%.3f, %.3f) m, heading %.2f deg" % (x, y, math.degrees(th)))
    # 2. left wheel 1 % bigger than expected
    x, y, th = drive_square(2.0, 0.4, 1.0, true_r_scale=(1.0, 1.01))
    print("left wheel +1 %%    : end (%.3f, %.3f) m -> error %.3f m" % (x, y, math.hypot(x, y)))
    # 3. track 3 % wider than expected, ccw and cw
    for ccw in (True, False):
        x, y, th = drive_square(2.0, 0.4, 1.0, true_track_scale=1.03, ccw=ccw)
        print("track +3 %% %s: end (%.3f, %.3f) m -> error %.3f m" % ("CCW" if ccw else "CW ", x, y, math.hypot(x, y)))
    # 4. random slip 1 %: 20 runs
    errs = []
    for s in range(20):
        x, y, th = drive_square(2.0, 0.4, 1.0, noise=0.01, seed=s)
        errs.append(math.hypot(x, y))
    m = sum(errs) / len(errs); sd = (sum((e - m) ** 2 for e in errs) / (len(errs) - 1)) ** 0.5
    print("random slip 1 %%    : mean error %.3f m, std %.3f m (20 runs)" % (m, sd))

14.4 Three simple calibration tests

  1. Distance (wheel radius). Drive straight for a long, measured distance Dtrue (a tape on the floor, 5 to 10 m). Read the odometry distance Dodo. Then rnew = r × Dtrue / Dodo. Do it for the left and for the right wheel (or check that the robot ends on the line: if it curves, one wheel is relatively bigger).
  2. Rotation (track width). Spin on the spot for 10 full turns (measure the real angle with a mark on the floor, or with a good gyroscope). If odometry says θodo and the truth is θtrue, then Lnew = L × θodo / θtrue. (Derivation: Δθ = (ΔsR − ΔsL) / L, so the angle is inversely proportional to L.) For skid-steer robots this gives the effective track χ L of lesson 8.
  3. Check with the square. Drive the square both ways with the new values and measure the end points. The clusters must be near the start and not on one side.
Worked example

Straight test: the tape says 8.00 m, the odometry says 8.12 m. Then rnew = 0.05 × 8.00 / 8.12 = 0.04926 m (−1.5 %). Spin test: 10 turns = 3 600°; the odometry says 3 600° but a gyroscope measured 3 540°. Then the odometry over-estimates the angle by 1.7 %, so Lnew = 0.30 × 3 600 / 3 540 = 0.3051 m.

14.5 What a gyroscope adds (and its trap)

A gyroscope measures the turning rate ω directly, without wheel slip. Integrated, it gives a heading that is much better than the one from the wheels, especially for skid-steer and Mecanum robots. The usual fusion is simple: heading from the gyroscope, distance from the wheels. The trap is the bias: a gyroscope that reads 0.5°/s when it is still gives, after one minute, an error of 30°. So: (1) estimate the bias by averaging the output while the robot is stopped (a few seconds at start-up); (2) re-estimate it every time the robot stops; (3) with a bias of only 0.01°/s the same minute gives 0.6°; (4) correct the remaining drift with an absolute sensor (lesson 15).

The rule of the professionals

Odometry is never “right”, it is only less wrong than nothing for a short time. Calibrate it, give it a gyroscope, and then correct it with something that does not drift. Lesson 15 shows how to combine them correctly.

Knowing where you are: the Kalman filter and the EKF

24 min
You will learn

to combine a drifting odometry with an absolute measurement using an extended Kalman filter (EKF), to read a covariance matrix, and to write and test the filter.

15.1 The idea in one dimension

Two sources give an estimate of your position, each with its uncertainty (variance): the prediction from odometry, with the variance P, and a measurement (a GPS, a lidar match) with the variance R. The best combination is the average weighted by the confidence:

K = P / ( P + R )    x ← xpred + K ( z − xpred )    P ← ( 1 − K ) P

K is the Kalman gain, between 0 (trust the prediction) and 1 (trust the measurement). Example: P = 0.04 m² (σ = 20 cm) and R = 0.01 m² (σ = 10 cm): K = 0.04 / 0.05 = 0.8, the new variance is 0.2 × 0.04 = 0.008 m² (σ = 8.9 cm): the result is better than both sources.

15.2 The EKF for the pose of a robot

For the pose, the state is the vector μ = ( x , y , θ ) and the covariance matrix Σ (3 × 3) describes the uncertainty: the diagonal holds the variances, the other terms the correlations (they tell, for example, that a heading error produces a position error). Because the motion is nonlinear (cos θ, sin θ), we linearise it with its Jacobian G: this is the “extended” Kalman filter. Two steps repeat:

Prediction (every odometry step):   μ ← ( x + v Δt cos θ ,   y + v Δt sin θ ,   θ + ω Δt )    Σ ← G Σ GT + Q

G = 10−v Δt sin θ01v Δt cos θ001

Update (when a measurement z arrives, z = H μ + noise of covariance R):   K = Σ HT ( H Σ HT + R )−1    μ ← μ + K ( z − H μ )    Σ ← ( I − K H ) Σ

For a sensor that measures the position (GPS, total station, a landmark with known place) H = ( 1 0 0 ; 0 1 0 ). For a compass or a gyroscope-corrected heading H = ( 0 0 1 ). The difference z − H μ is the innovation: how much the measurement surprises the filter. If its size is large compared with its expected covariance (H Σ HT + R), the measurement is probably an outlier and must be rejected: this is the Mahalanobis gate d² = νT S−1 ν < 9.21 (99 % for 2 degrees of freedom).

15.3 The code, and what it prints

import numpy as np

def predict(mu, S, v, w, dt, q):
    x, y, th = mu
    mu_new = np.array([x + v * dt * np.cos(th), y + v * dt * np.sin(th), th + w * dt])
    G = np.array([[1, 0, -v * dt * np.sin(th)],
                  [0, 1,  v * dt * np.cos(th)],
                  [0, 0, 1]])
    return mu_new, G @ S @ G.T + np.diag(q)

def update(mu, S, z, H, R):
    innov = z - H @ mu
    Sinn = H @ S @ H.T + R
    K = S @ H.T @ np.linalg.inv(Sinn)
    mu_new = mu + K @ innov
    S_new = (np.eye(3) - K @ H) @ S
    return mu_new, S_new, innov, Sinn

15.4 Tuning and checking a filter like a professional

  • Q (process noise) describes how wrong the odometry can be between two steps. Too small: the filter trusts odometry too much and reacts slowly to measurements. Too large: it trusts every noisy measurement. Start from the odometry errors measured in lesson 14.
  • R (measurement noise) comes from the data sheet of the sensor and from measurements at rest (the variance of the readings).
  • Consistency check: the normalised innovation squared d² must average the number of measurement dimensions (2 for a position fix). If it is always much larger, the filter is over-confident (raise Q or R); much smaller, it is too cautious.
  • Always normalise angles to (−π, π] after every update, and use angle differences, never plain subtraction.
  • Timestamps: a measurement is about the past. Use the pose of the filter at the time of the measurement, not the latest one, or you inject an error of v × delay.
  • In ROS 2 you rarely write the EKF yourself: the robot_localization package (ekf_node) and Nav2's AMCL (a particle filter on a map) do it. You still have to choose Q, R and the frames, so you must understand what they mean.

Dynamics and sizing: forces, motors, traction, tipping and battery

26 min
You will learn

to compute the force, torque, speed and power that a mobile robot needs, to choose the motor and the gear ratio, to check traction and tipping, and to size the battery.

Up to now we ignored forces. A professional cannot: a robot with a perfect kinematic model that cannot climb its ramp, or whose battery lasts 40 minutes instead of 6 hours, is a failed robot. This lesson is the method, step by step.

16.1 The force the wheels must produce

Newton: the force at the ground is the sum of three terms (air drag is negligible below a few m/s):

F = m a + crr m g cos α + m g sin α

  • m a: accelerate the whole mass (robot + payload);
  • crr m g: rolling resistance, with the coefficient crr that depends on the wheel and the floor (very roughly 0.01 for hard wheels on a smooth floor, 0.02 to 0.05 for soft wheels, carpet or poor floors: measure it, lab 5);
  • m g sin α: climb a slope of angle α (a 5 % slope has tan α = 0.05, α = 2.86°).

16.2 From force to motor torque and speed

With n driven wheels of radius r, a gearbox of ratio G and efficiency ηg (about 0.8 to 0.9 for a planetary gearbox, much less for a worm gear):

τwheel = F r / n    τmotor = τwheel / ( G ηg )    ωmotor = G v / r    nrpm = ωmotor × 60 / 2π

Worked example: a 60 kg AMR

m = 60 kg (robot + load), r = 0.10 m, two driven wheels, G = 20, ηg = 0.85, crr = 0.02, slope 5 %, v = 1.2 m/s, a = 0.5 m/s².
Forces: m a = 30 N; rolling = 0.02 × 60 × 9.81 = 11.8 N; slope = 60 × 9.81 × sin 2.86° = 29.4 N. Total F = 71.2 N.
Per wheel: τwheel = 71.2 × 0.10 / 2 = 3.56 N·m. Per motor: 3.56 / (20 × 0.85) = 0.209 N·m. Motor speed: 12 rad/s at the wheel × 20 = 240 rad/s = 2 292 rpm.

16.3 Choosing the motor: peak, continuous and RMS

A motor has two torque ratings: the peak torque (for a few seconds: the acceleration) and the continuous torque (what it can give for ever without overheating). The heating is proportional to the square of the torque, so what must stay under the continuous rating is the RMS torque over the work cycle:

τRMS = √( ( Σ τi² ti ) / Σ ti )

Worked example (same AMR)

Cycle of 40 s: accelerate 2 s (0.209 N·m), cruise 30 s (0.121 N·m), brake 2 s (0.033 N·m), stopped 6 s (0). τRMS = √( ( 2 × 0.209² + 30 × 0.121² + 2 × 0.033² ) / 40 ) = 0.115 N·m. With a margin of 1.5: choose a motor with a continuous torque ≥ 0.17 N·m and a peak torque ≥ 0.31 N·m, at 2 292 rpm or more. Do not forget that the robot must also hold on the slope when it stops: a brake or a torque of 0.12 N·m, which is why a failsafe brake is used.

Other checks of a professional: the supply voltage must allow the speed (back-EMF); the gear ratio trades torque for speed (a higher ratio needs a smaller motor but a higher motor speed, and a gearbox that is harder to back-drive); the current of the peak must be supplied by the drive and the battery; the encoder must be on the motor shaft for resolution (lesson 14).

16.4 Traction and tipping

The wheels can push with at most μ times the load they carry, where μ is the friction coefficient (about 0.6 for rubber on a dry floor, much lower when wet). With all the weight on the driven wheels the maximum acceleration is amax = μ g = 5.9 m/s² and the steepest slope is tan α ≤ μ (31° for μ = 0.6). If only a fraction f of the weight is on the driven wheels (for example 80 % for a differential robot with castors), multiply the limit by f. For the AMR: 0.6 × 60 × 9.81 × 0.8 = 282 N available against 71 N needed: the traction is fine.

Tipping. Let h be the height of the centre of gravity, b its distance to the front or rear wheel line (about half the wheelbase) and T the track. The robot tips forward when braking harder than a = g b / h, sideways in a turn when the lateral acceleration v² / R exceeds g T / (2 h), and sideways on a slope steeper than arctan( T / (2 h) ). Example h = 0.4 m, b = 0.3 m, T = 0.5 m: 7.4 m/s², 6.1 m/s² and 32°. The robot should slip before it tips: these limits must be larger than μ g = 5.9 m/s². With a tall robot (h = 0.9 m) the braking limit falls to 3.3 m/s²: it would tip before it slips, and you must limit the deceleration in software.

16.5 Power, energy and battery

At cruise the robot has no acceleration: the mechanical power is Pm = ( crr m g cos α + m g sin α ) v. The electrical power adds the losses (gearbox, motor, drive: an overall efficiency η of about 0.6 to 0.8) and the consumption of the computer, sensors and brakes. The battery is not fully usable (about 80 % to protect its life):

Pel = Pm / η + Pelectronics     runtime = 0.8 × Ebattery / Pel

Worked example (same AMR)

Cruise force on the slope: 11.8 + 29.4 = 41.2 N, so Pm = 41.2 × 1.2 = 49.4 W. With η = 0.7 and 30 W of electronics: Pel = 49.4 / 0.7 + 30 = 100.6 W. A 24 V, 20 Ah battery stores 480 Wh, of which 384 Wh are usable: runtime = 384 / 100.6 = 3.8 h (on a permanent 5 % slope; on the flat the robot would last much longer). The current is 100.6 / 24 = 4.2 A, that is 0.21 C: easy for the battery. For a 6 h mission at this power you need 6 × 100.6 / 0.8 = 755 Wh.

Pitfall: the “wish list” budget

Never size with the nominal case only. List the worst case (heaviest payload, steepest ramp, lowest battery voltage, worst floor, cold battery) and the typical case (for the runtime). Add a margin of 30 to 50 % on the torque, and measure the real power on the real robot (lab 5): a prediction within 25 % is a good result.

16.6 The control loops of a wheel

A real robot nests loops, each about 5 to 10 times faster than the one above: the current (torque) loop of the motor drive (kHz), the wheel speed loop (a PI controller with the encoder, 100 to 1 000 Hz), and above it the body loop of lessons 11 and 12 (20 to 100 Hz), which produces the wheel speed references. Add a feed-forward (the speed command times the motor constant) so that the PI only corrects the small errors, and limit the acceleration (a ramp) so that the wheels never ask for more than the traction allows.

A good module is small, uses SI units everywhere, has no hidden state except the odometry, scales the wheel commands when a motor saturates (lesson 8), limits the acceleration, and comes with unit tests. Here is a complete one (diffdrive.py), with the controller of lesson 11 used on top of it:

import math

class DiffDrive:
    """Kinematics, limits and odometry of a differential-drive robot (SI units, radians)."""
    def __init__(self, radius, track, max_wheel_speed, max_accel=None):
        self.r, self.L, self.wmax, self.amax = radius, track, max_wheel_speed, max_accel
        self.x = self.y = self.th = 0.0
        self.cmd = (0.0, 0.0)                          # last wheel speeds sent (rad/s): right, left

    def wheel_speeds(self, v, w, dt=None):
        """body (v, w) -> wheel angular speeds (right, left), scaled if a motor would saturate
        and limited in acceleration if dt is given."""
        wr = (v + w * self.L / 2) / self.r
        wl = (v - w * self.L / 2) / self.r
        s = max(1.0, abs(wr) / self.wmax, abs(wl) / self.wmax)       # scale BOTH wheels by the same factor
        wr, wl = wr / s, wl / s
        if self.amax and dt:                                         # ramp: limit the change per step
            dmax = self.amax * dt / self.r
            wr = min(max(wr, self.cmd[0] - dmax), self.cmd[0] + dmax)
            wl = min(max(wl, self.cmd[1] - dmax), self.cmd[1] + dmax)
        self.cmd = (wr, wl)
        return wr, wl

    def body_speeds(self, wr, wl):
        return self.r * (wr + wl) / 2, self.r * (wr - wl) / self.L

    def integrate(self, wr, wl, dt):
        """odometry from the measured wheel speeds (midpoint rule)."""
        ds = self.r * (wr + wl) / 2 * dt
        dth = self.r * (wr - wl) / self.L * dt
        self.x += ds * math.cos(self.th + dth / 2)
        self.y += ds * math.sin(self.th + dth / 2)
        self.th += dth
        return self.x, self.y, self.th

def go_to_goal(robot, kr=1.5, ka=6.0, kb=-2.0, tol=0.01, dt=0.02, t_max=60.0):
    """Lesson 11 controller (goal = origin, heading 0)."""
    wrap = lambda a: (a + math.pi) % (2 * math.pi) - math.pi
    t = 0.0
    while t < t_max:
        rho = math.hypot(robot.x, robot.y)
        if rho < tol:
            break
        gamma = math.atan2(-robot.y, -robot.x)
        alpha = wrap(gamma - robot.th); th = robot.th; sign = 1.0
        if abs(alpha) > math.pi / 2:                    # goal behind: drive backwards
            th += math.pi; alpha = wrap(gamma - th); sign = -1.0
        beta = wrap(-th - alpha)
        v = sign * kr * rho; w = ka * alpha + kb * beta
        wr, wl = robot.wheel_speeds(v, w, dt)
        robot.integrate(wr, wl, dt)
        t += dt
    return t

17.3 ROS 2 in ten minutes

  • Nodes are programs that exchange messages on named topics (publish / subscribe), call services (request / reply) and run long tasks with actions (goal, feedback, result). Nav2 uses actions: “navigate to this pose”.
  • The command: the topic cmd_vel, message geometry_msgs/Twist: linear.x is v (m/s, forward), angular.z is ω (rad/s, counter-clockwise). For a holonomic robot linear.y is the sideways speed. This single message is the interface between the whole navigation and your robot base.
  • The odometry: nav_msgs/Odometry on odom (pose and twist with covariances) and the transform odom → base_link in tf2.
  • Conventions (REP-103 and REP-105): SI units and radians; x forward, y left, z up; the frames map → odom → base_link: odom is smooth but drifts (wheel odometry), map is globally correct but may jump (localisation). The localisation publishes the map → odom correction, which is exactly the EKF update of lesson 15.
  • Existing building blocks: ros2_control with the diff_drive_controller (parameters wheel_separation, wheel_radius, velocity and acceleration limits, a cmd_vel timeout) does the kinematics of this lesson; robot_localization does the EKF; Nav2 provides planners (NavFn, Smac Hybrid-A* with Dubins or Reeds–Shepp motions) and controllers (DWB, MPPI, Regulated Pure Pursuit). Your work is to give them the right numbers: r, L, limits, covariances.

18.1 Stopping distance and safe speed

When an obstacle appears, the robot first travels during the reaction time tr (sensor, computer, communication, brake delay), then brakes with the deceleration a:

sstop = v tr + v² / ( 2 a )     for a free distance d:   vsafe = −a tr + √( ( a tr )² + 2 a d )

Worked example

tr = 0.3 s and a = 1.0 m/s². At 0.5 m/s: 0.15 + 0.125 = 0.28 m. At 1.0 m/s: 0.30 + 0.50 = 0.80 m. At 1.5 m/s: 0.45 + 1.125 = 1.58 m. The distance grows with the square of the speed, so doubling the speed more than doubles it. If the free distance in front of the robot is 1.0 m, the maximum safe speed is −0.3 + √( 0.09 + 2 ) = 1.15 m/s. A professional adds a margin (sensor range tolerance, floor slip, the size of the robot): usually 0.2 to 0.5 m.

This is how speed-dependent protective fields of safety laser scanners work: the faster the robot, the longer the field in front of it, and the robot slows down when something enters a larger “warning” field before the “protective” one that triggers the stop.

18.2 Safety functions and standards

  • Emergency stop: a red button on a yellow background, hardware-wired (not only software), that removes the energy to the motors, reachable on every side.
  • Safe Torque Off (STO): a function of the motor drive that removes the torque safely, certified (IEC 61800-5-2). Fail-safe brakes (applied when the power is off) hold the robot on a slope.
  • Safety-rated sensors: a safety laser scanner with switchable protective fields, and mechanical bumpers with a contact switch as the last barrier.
  • Speed and force limits in the zones where people walk, and a watchdog on every command (lesson 17).
  • Visible and audible warnings (lights, beeper), and a tested procedure for recovery.

Relevant standards (the names to look for; always use the current edition and your own safety officer): ISO 3691-4 (driverless industrial trucks and their systems), ANSI/RIA R15.08 (industrial mobile robots, in North America), ISO 13849-1 (performance levels of safety-related control parts), ISO 12100 (risk assessment and reduction), IEC 62061 and IEC 61508 (functional safety), the EU Machinery Directive / Regulation for CE marking, and the ISO 18646 series (performance criteria and test methods of wheeled service robots). The method of the risk assessment is the same as for arms (see the “real world” course): hazard, severity, exposure, possibility to avoid it, then measures.

Software is not a safety function

A navigation program, however good, can crash or be wrong. Whatever protects a human (emergency stop, STO, protective field, brakes) must be a separate, certified chain that works even if the navigation software has failed. Never rely on cmd_vel = 0 to protect a person.

18.3 How to test: a plan, metrics and statistics

A test is not “I tried and it worked”. Write the plan before: the question, the setup, the number of repetitions, the metric, the pass criterion (a number), and what you do if it fails. Metrics to use for a wheeled robot:

But the requirement is often about every run, not the mean: so check mean + 2σ or the maximum, and run enough tests to see the rare failures (to be 95 % sure that the success rate is at least 99 % you need about 300 successes in a row).

Lab 3 (software): path tracking with a lag, measured

Goal: find by experiment the look-ahead distance that works at 1.0 m/s with a 0.4 s lag, and explain it. Tools: Python 3 and the file below.

import math

# Wavy reference path y = 0.8 sin(0.6 x), 5 cm between points
PATH = [(0.05 * i, 0.8 * math.sin(0.6 * 0.05 * i)) for i in range(0, 281)]

def pure_pursuit(ld, v, lag, start=(0.0, -0.4, 0.0), w_max=2.5, dt=0.02):
    """Differential robot with pure pursuit and a first-order lag on the turning rate.
    Returns (max cross-track error, RMS error, finished). The first 3 s are ignored (start offset)."""
    x, y, th = start
    w_actual, idx, t = 0.0, 0, 0.0
    sse, n, emax = 0.0, 0, 0.0
    while t < 60.0:
        # nearest path point (search only a small window ahead of the last one)
        window = range(max(0, idx - 5), min(len(PATH), idx + 80))
        idx = min(window, key=lambda i: math.hypot(PATH[i][0] - x, PATH[i][1] - y))
        e = math.hypot(PATH[idx][0] - x, PATH[idx][1] - y)
        if idx >= len(PATH) - 3:
            return emax, math.sqrt(sse / max(n, 1)), True
        # look-ahead target: first path point farther than ld from the robot
        j = idx
        while j < len(PATH) - 1 and math.hypot(PATH[j][0] - x, PATH[j][1] - y) < ld:
            j += 1
        gx, gy = PATH[j][0] - x, PATH[j][1] - y
        xr = math.cos(th) * gx + math.sin(th) * gy        # target in the robot frame
        yr = -math.sin(th) * gx + math.cos(th) * gy
        kappa = 2.0 * yr / (xr * xr + yr * yr)            # pure pursuit curvature
        w_cmd = max(-w_max, min(w_max, v * kappa))
        w_actual += (w_cmd - w_actual) * dt / lag if lag > 0 else (w_cmd - w_actual)
        x += v * math.cos(th) * dt; y += v * math.sin(th) * dt; th += w_actual * dt
        t += dt
        if t > 3.0:
            emax = max(emax, e); sse += e * e; n += 1
        if abs(y) > 20:
            return emax, math.sqrt(sse / max(n, 1)), False
    return emax, math.sqrt(sse / max(n, 1)), False
