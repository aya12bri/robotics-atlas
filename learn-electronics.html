Voltage, current, resistance and power

25 min
You will learn

what a voltage, a current and a resistance are, Ohm's law U = R I, the power P = U I, how to choose the resistor of an LED, and the voltage divider used to measure a battery.

In one sentence

The voltage pushes, the resistance brakes, and the current is what flows: U = R × I.

1.1 Three quantities

QuantitySymbol, unitPicture with waterIn a robot
voltageU, volt (V)the pressurebattery 7.4 V, logic 5 V or 3.3 V
currentI, ampere (A)the flowan LED 15 mA, a motor 1 A, a servo blocked 2 A
resistanceR, ohm (Ω)a narrow pipe220 Ω for an LED, 10 kΩ for a button
powerP, watt (W)the work done per secondwhat heats a resistor, what a motor gives

U = R I   P = U I = R I²

1.2 The resistor of an LED

An LED always takes about the same voltage (≈ 2 V for red, ≈ 3 V for blue or white) whatever the current, so it cannot limit its own current: without a resistor it burns. The resistor takes the rest of the voltage, and Ohm's law gives its value:

R = (Usupply − ULED) / I = (5 − 2) / 0.015 = 200 Ω → 220 Ω (the next standard value)

1.3 The voltage divider

Two resistors in series share the voltage in proportion to their values. With R1 = R2 = 10 kΩ, a 2S battery full at 8.4 V gives 4.2 V: below the 5 V that an Arduino input accepts, so the robot can watch its battery on A0.

Safety first
  • Never connect + to − directly (a short circuit): a LiPo can then give 50 A and catch fire.
  • Wire with the power off; check the polarity twice before switching on.
  • A resistor has a maximum power (often 0.25 W): check P = R I².

Key terms

  • voltage (V)
  • current (A)
  • resistance (Ω)
  • Ohm's law, U = R I
  • power (W)
  • voltage divider

  3. With R1 = R2, what fraction of the input voltage do you get at the middle?

Batteries and regulators: powering a robot

25 min
You will learn

the batteries of small robots (LiPo, Li-ion, NiMH), their voltage and capacity, how long a robot runs, why the logic and the motors are powered separately, and the difference between a linear regulator and a buck converter.

In one sentence

The battery gives the energy, the regulator makes a clean 5 V for the brain, and the motors take their power directly — with one common ground.

2.1 Batteries

TypeVoltage of one cellStrong pointsCare
LiPo3.7 V (4.2 full, 3.3 empty)light, very high currentspecial charger, never below 3.0 V, fire risk if punctured
Li-ion 186503.6 Vhigh capacity, robust caseprotection board (BMS)
NiMH1.2 Vsafe, cheapheavy, lower current

Cells are put in series to add their voltages: a 2S LiPo = 2 cells = 7.4 V. The capacity in mAh says how long it lasts:

autonomy (h) ≈ capacity (Ah) / average current (A)   2.2 Ah / 1.1 A = 2 h

2.2 One battery, two circuits

  • Motors make big current peaks and electrical noise; if they share the 5 V of the Arduino, it resets when they start.
  • So the logic gets its own regulated 5 V, and the motors are powered by the driver straight from the battery.
  • All the grounds (GND) are connected: a voltage is always measured against a reference, and a signal without a common ground means nothing.

2.3 Linear regulator or buck converter?

Linear (7805, AMS1117)Buck (switching)
howburns the extra voltage as heatswitches fast and stores energy in a coil
lost power(Vin − Vout) × I: (7.4 − 5) × 0.5 = 1.2 W≈ 10 % (efficiency ≈ 90 %)
whensmall currents, very clean voltagebatteries, currents above 0.3 A

3.2 The first program

// blink: the LED on pin 13 turns on and off every half second
const int LED = 13;              // pin 13 (the board's own LED is on it too)

void setup() {                   // runs once, at power-on or reset
  pinMode(LED, OUTPUT);          // pin 13 gives a voltage
  Serial.begin(9600);            // open the link to the computer
}

void loop() {                    // runs again and again, forever
  digitalWrite(LED, HIGH);       // 5 V: the LED is on
  Serial.println("on");
  delay(500);                    // wait 500 ms
  digitalWrite(LED, LOW);        // 0 V: the LED is off
  Serial.println("off");
  delay(500);
}

  2. Choose the board (Arduino Uno) and the port in the Tools menu.
  3. Click Upload (→); the LED blinks once per second.
  4. Open the Serial Monitor at 9600 baud: it prints on, off, on, off…
Same ideas as Python, different words

The Arduino language is C++: each instruction ends with ;, blocks are between { } instead of indentation, and each variable has a declared type (int, float, bool). loop() is the while True: of the Python course, lesson 3.

Reading sensors: buttons, analog voltages, ultrasound

30 min
You will learn

how to read a button with a pull-up resistor, how to read a voltage with analogRead and turn it into volts, and how an ultrasonic sensor measures a distance from an echo time.

In one sentence

Every sensor finally gives a voltage or a time; the program turns it into a physical quantity with a simple formula.

4.1 A button and its pull-up resistor

An input that is connected to nothing “floats” and reads random values. The pull-up resistor holds it at 5 V; the button, when pressed, connects it to GND. So the logic is inverted: pressed = LOW. INPUT_PULLUP uses the resistor already inside the chip: no extra part.

4.2 An analog voltage

V = n × 5 / 1023   n = analogRead(A0) ∈ [0, 1023]

A potentiometer (a resistor with a slider) between 5 V and GND is a voltage divider you turn by hand: its middle pin gives 0 to 5 V. Light, temperature and battery sensors work the same way.

4.3 Measuring a distance with sound

The HC-SR04 sends a burst of ultrasound when TRIG gets a 10 µs pulse; ECHO then stays HIGH for the time the sound takes to go to the obstacle and come back. Sound travels at 343 m/s = 0.0343 cm/µs:

d = t × 0.0343 / 2   (the 2: there and back)

// a push button (pull-up), a potentiometer and an HC-SR04 ultrasonic sensor
const int BUTTON = 2, TRIG = 9, ECHO = 10;

void setup() {
  pinMode(BUTTON, INPUT_PULLUP); // internal resistor to 5 V: reads HIGH when released
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  Serial.begin(9600);
}

float distance_cm() {
  digitalWrite(TRIG, LOW);  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH); delayMicroseconds(10);   // a 10 us pulse starts a measurement
  digitalWrite(TRIG, LOW);
  unsigned long t = pulseIn(ECHO, HIGH, 30000);      // echo time in us (0 if nothing within 30 ms)
  return t * 0.0343 / 2;                             // sound: 343 m/s = 0.0343 cm/us, there and back
}

void loop() {
  bool pressed = digitalRead(BUTTON) == LOW;         // pressed = connected to GND
  int n = analogRead(A0);                            // 0 ... 1023
  float volts = n * 5.0 / 1023;
  Serial.print(pressed ? "pressed  " : "released ");
  Serial.print(volts, 2);  Serial.print(" V  ");
  Serial.print(distance_cm(), 1); Serial.println(" cm");
  delay(200);
}

Range about 2 cm to 4 m; a soft or slanted surface may send no echo (pulseIn then returns 0 after its timeout); two sensors firing together disturb each other. Lesson 8 shows how the robot handles a missing echo.

PWM and transistors: controlling power

30 min
You will learn

how PWM makes an “average” voltage with a signal that is only on or off, what analogWrite does, why a motor needs a transistor (a MOSFET) and a flyback diode, and how to wire them.

In one sentence

PWM switches the full voltage on and off very fast; the motor only feels the average, set by the fraction of time it is on.

5.1 The duty cycle

duty = value / 255   Uaverage = duty × Usupply

The dashed yellow line is the average. The same PWM dims an LED, sets the speed of a motor or the heat of a resistor. It is efficient: the switch is either fully on (no voltage across it) or fully off (no current), so it hardly heats.

5.2 A transistor as a switch

  • The pin only drives the gate of the MOSFET (almost no current); the motor current flows from the motor supply through the MOSFET to GND.
  • Choose a logic-level MOSFET: fully on with 5 V (or 3.3 V) on the gate.
  • A motor is a coil: when it is switched off, it creates a high voltage spike. The flyback diode, across the motor, lets that current go round and protects the MOSFET.
// PWM: the speed of a DC motor through a MOSFET on pin 5, set by a potentiometer on A0
const int MOTOR = 5;             // a PWM pin (marked ~ on the board)

void setup() {
  pinMode(MOTOR, OUTPUT);
}

void loop() {
  int n = analogRead(A0);        // 0 ... 1023
  int duty = n / 4;              // 0 ... 255
  analogWrite(MOTOR, duty);      // 0 = always off, 255 = always on, 128 = on half the time
  delay(20);
}
One direction only

This circuit can only set the speed. To also choose the direction, four switches are needed: the H-bridge of the next lesson.

The DC motor: H-bridge and encoder

30 min
You will learn

how an H-bridge chooses the direction of a DC motor, how to drive it with a driver board, how an encoder counts the turns and gives the direction, and how to compute the speed of a wheel.

In one sentence

The H-bridge reverses the current to reverse the motor; the encoder counts ticks so that the robot knows how far and how fast its wheels turned.

6.1 The H-bridge

IN1IN2PWMMotor
HIGHLOW0 … 255forward, speed set by PWM
LOWHIGH0 … 255backward
LOWLOW—free wheel (coasts)
HIGHHIGH—brake (motor short-circuited)

Never close S1 and S2 (or S3 and S4) together: that is a short circuit of the battery. Driver boards (TB6612FNG, L298N, DRV8833) contain the four switches and the protections; you only give IN1, IN2 and PWM. The L298N, older, loses about 2 V; the TB6612 almost nothing.

6.2 The encoder

Two signals A and B, shifted by a quarter period (in quadrature). On each rising edge of A, look at B: LOW → one way, HIGH → the other way. An interrupt on A counts the ticks even while loop() is busy.

speed (turns/s) = Δticks / (CPR × Δt)   v = turns/s × π D

// a DC motor through an H-bridge (TB6612 or L298N) and its encoder: direction, PWM, speed
const int PWMA = 5, AIN1 = 7, AIN2 = 8;   // driver: speed and direction
const int ENC_A = 2, ENC_B = 4;           // encoder: A on an interrupt pin
volatile long ticks = 0;
const float CPR = 360.0;                  // ticks per turn of the wheel (encoder x gearbox)

void onA() { ticks += (digitalRead(ENC_B) == HIGH) ? -1 : +1; }   // B tells the direction

void drive(int u) {                       // u from -255 (full back) to +255 (full forward)
  digitalWrite(AIN1, u >= 0 ? HIGH : LOW);
  digitalWrite(AIN2, u >= 0 ? LOW : HIGH);
  analogWrite(PWMA, constrain(abs(u), 0, 255));
}

void setup() {
  pinMode(PWMA, OUTPUT); pinMode(AIN1, OUTPUT); pinMode(AIN2, OUTPUT);
  pinMode(ENC_A, INPUT_PULLUP); pinMode(ENC_B, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(ENC_A), onA, RISING);
  Serial.begin(115200);
}

void loop() {
  static long last = 0;
  drive(150);                              // forward at about 60 %
  delay(100);                              // every 100 ms
  noInterrupts(); long now = ticks; interrupts();
  float rpm = (now - last) / CPR / 0.1 * 60;   // turns per second x 60
  last = now;
  Serial.println(rpm);
}
CPR: count it, do not guess it

CPR is the number of ticks per turn of the wheel = ticks of the encoder per motor turn × gear ratio (× 2 or 4 if both edges are counted). Turn the wheel exactly 10 times by hand and read the count: you get CPR to 0.1 %.

    S3 and S2: the current crosses the motor from right to left.

  2. Why use an interrupt for the encoder?

    Ticks come fast and at any time; an interrupt counts each one at once, even during a delay or a print.

Servos and stepper motors

25 min
You will learn

how a hobby servo is told an angle with the width of a pulse, how a stepper motor turns by exact steps, microstepping, and how to choose between a DC motor, a servo and a stepper.

In one sentence

A servo goes to an angle and holds it by itself; a stepper turns by exact steps without any sensor.

7.1 The servo

Inside a servo there is a DC motor, a gearbox, a potentiometer that measures the output angle, and a small board that does the control: it compares the angle asked by the pulse with the measured one and drives the motor until they match — the closed loop of lesson 8, already built in.

pulse (ms) = 1 + angle / 180   (1 ms → 0°, 2 ms → 180°; many servos use 0.5–2.5 ms)

7.2 The stepper motor

A stepper has several coils that the driver switches in turn: each pulse on STEP moves the shaft by one step, usually 1.8° (200 steps per turn). With microstepping (1/16 on an A4988) the driver doses the currents to make 3200 smaller steps per turn: smoother and quieter. It needs no encoder as long as it does not skip steps (too much load or too fast).

// a hobby servo on pin 9 and a stepper motor through an A4988 driver (STEP on 3, DIR on 4)
#include <Servo.h>
Servo s;
const int STEP = 3, DIR = 4;

void setup() {
  s.attach(9);                   // a pulse every 20 ms, 1 ms = 0 deg ... 2 ms = 180 deg
  pinMode(STEP, OUTPUT); pinMode(DIR, OUTPUT);
}

void loop() {
  s.write(0);   delay(1000);     // go to 0 deg
  s.write(90);  delay(1000);     // 1.5 ms pulse: the middle
  s.write(180); delay(1000);

  digitalWrite(DIR, HIGH);       // one way
  for (int i = 0; i < 200; i++) {   // 200 full steps = 1 turn (1.8 deg per step)
    digitalWrite(STEP, HIGH); delayMicroseconds(1000);
    digitalWrite(STEP, LOW);  delayMicroseconds(1000);   // 2 ms per step: 1 turn in 0.4 s
  }
  delay(500);
}

8.2 The proportional controller

e = d − 20 cm   u = Kp e, limited to ±200   u = 0 if |e| < 1 cm

  • Too far (e > 0): the robot goes forward; too close (e < 0): it goes back; the bigger the error, the faster.
  • The saturation at ±200 keeps the speed reasonable and the PWM inside 0…255.
  • The dead band of ±1 cm stops the robot from buzzing back and forth around the target because of sensor noise.
  • millis() gives a fixed period of 50 ms without delay(), so the loop could do other things in between.
// a first robot: two wheels keep the robot 20 cm from a wall with a proportional controller
const int TRIG = 9, ECHO = 10;
const int PWMA = 5, AIN1 = 7, AIN2 = 8, PWMB = 6, BIN1 = 11, BIN2 = 12;
const float TARGET = 20.0, KP = 12.0;     // cm, PWM units per cm
const unsigned long PERIOD = 50;          // ms: the loop runs at 20 Hz

float distance_cm() {
  digitalWrite(TRIG, LOW);  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH); delayMicroseconds(10); digitalWrite(TRIG, LOW);
  unsigned long t = pulseIn(ECHO, HIGH, 30000);
  return t == 0 ? 400 : t * 0.0343 / 2;   // no echo: treat as far away
}

void wheel(int pwm, int in1, int in2, int u) {
  digitalWrite(in1, u >= 0 ? HIGH : LOW); digitalWrite(in2, u >= 0 ? LOW : HIGH);
  analogWrite(pwm, constrain(abs(u), 0, 255));
}

void setup() {
  int outs[] = {TRIG, PWMA, AIN1, AIN2, PWMB, BIN1, BIN2};
  for (int p : outs) pinMode(p, OUTPUT);
  pinMode(ECHO, INPUT);
  Serial.begin(115200);
}

void loop() {
  static unsigned long next = 0;
  if (millis() < next) return;            // wait for the next period without blocking
  next = millis() + PERIOD;

  float d = distance_cm();                // 1. read
  float e = d - TARGET;                   // 2. compute: error > 0 = too far, go forward
  int u = constrain((int)(KP * e), -200, 200);
  if (abs(e) < 1.0) u = 0;                //    a dead band: no buzzing around the target
  wheel(PWMA, AIN1, AIN2, u);             // 3. command both wheels
  wheel(PWMB, BIN1, BIN2, u);
  Serial.print(d); Serial.print(" cm  u = "); Serial.println(u);
}
Test it step by step
  1. Wheels in the air: print d and u, move your hand in front of the sensor, check the signs.
  2. One wheel at a time: u = 100 must turn it forward; if not, swap AIN1 and AIN2 in the code (or the motor wires).
  3. On the floor with a small Kp (4), then increase it until the robot oscillates, and take half of that value.
  4. Keep a hand near the switch: a sign error makes the robot run into the wall.
