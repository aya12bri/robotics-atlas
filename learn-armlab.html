1.4 Forward kinematics of the 2-axis arm

File arm_fk2.py. The formulas are those of the maths course: the tool is the sum of the arrows of the two links.

"""Forward kinematics of a planar 2-axis arm: from the joint angles to the tool."""
import numpy as np

L1, L2 = 0.5, 0.4                      # link lengths (m)


def fk(theta1, theta2):
    """Joint angles (rad) -> positions of the elbow and of the tool (m)."""
    elbow = np.array([L1 * np.cos(theta1), L1 * np.sin(theta1)])
    tool = elbow + np.array([L2 * np.cos(theta1 + theta2), L2 * np.sin(theta1 + theta2)])
    return elbow, tool


if __name__ == '__main__':
    for deg in [(0, 0), (30, 45), (90, -90), (120, 60)]:
        q = np.radians(deg)
        elbow, tool = fk(*q)
        print(f'theta = {deg} deg  ->  elbow ({elbow[0]:6.3f}, {elbow[1]:6.3f})  '
              f'tool ({tool[0]:6.3f}, {tool[1]:6.3f})  reach {np.linalg.norm(tool):.3f} m')

Always test with poses you can check by eye
  • (0°, 0°): the arm is stretched along x, the tool must be at L1 + L2 = 0.9 m.
  • (90°, −90°): link 1 points up, link 2 points right: tool at (0.4, 0.5).
  • (30°, 45°): the value computed by hand in the maths course, (0.537, 0.636).

If one of these is wrong, the bug is in the code, not in the robot. This habit of “known poses” will save you hours on a real arm.

Any robot from its DH table

16 min
You will learn

to write one function that computes the pose of the tool of any serial arm from its DH table, in both conventions, and to check that they agree.

Drawing and adding arrows works for 2 joints, not for 6. The DH table (maths course, lessons 6 to 8) turns every robot into a list of rows; the code only needs the matrix of one row and a loop that multiplies them.

"""Forward kinematics of ANY serial arm from its DH table (standard or modified)."""
import numpy as np


def dh_std(theta, d, a, alpha):
    """Standard DH: Rot(z, theta) Trans(z, d) Trans(x, a) Rot(x, alpha)."""
    ct, st, ca, sa = np.cos(theta), np.sin(theta), np.cos(alpha), np.sin(alpha)
    return np.array([[ct, -st * ca,  st * sa, a * ct],
                     [st,  ct * ca, -ct * sa, a * st],
                     [0,       sa,       ca,      d],
                     [0,        0,        0,      1]])


def dh_mod(alpha, a, theta, d):
    """Modified DH (DHM): Rot(x, alpha) Trans(x, a) Rot(z, theta) Trans(z, d)."""
    ct, st, ca, sa = np.cos(theta), np.sin(theta), np.cos(alpha), np.sin(alpha)
    return np.array([[ct,      -st,   0,       a],
                     [st * ca, ct * ca, -sa, -d * sa],
                     [st * sa, ct * sa,  ca,  d * ca],
                     [0,        0,       0,       1]])


def fk(rows, joint, q):
    """rows: the DH table; joint(row, qi) -> the matrix of one row. Returns the 4x4 pose of the tool."""
    T = np.eye(4)
    for row, qi in zip(rows, q):
        T = T @ joint(row, qi)
    return T


# the 3-axis arm of the course: shoulder height 0.40 m, links 0.45 m and 0.38 m
STD = [(0.40, 0.00, np.pi / 2), (0.0, 0.45, 0.0), (0.0, 0.38, 0.0)]          # (d, a, alpha), theta = q
MOD = [(0.0, 0.00, 0.40), (np.pi / 2, 0.00, 0.0), (0.0, 0.45, 0.0), (0.0, 0.38, 0.0)]   # (alpha, a, d), theta = q (0 for the tool)

std_joint = lambda row, qi: dh_std(qi, row[0], row[1], row[2])
mod_joint = lambda row, qi: dh_mod(row[0], row[1], qi, row[2])

if __name__ == '__main__':
    q = np.radians([25, 70, -80])
    T_std = fk(STD, std_joint, q)
    T_mod = fk(MOD, mod_joint, list(q) + [0.0])        # the fixed tool row has theta = 0
    np.set_printoptions(precision=3, suppress=True)
    print('tool position, standard DH :', T_std[:3, 3])
    print('tool position, modified DH :', T_mod[:3, 3])
    print('same pose (position and orientation):', np.allclose(T_std, T_mod))
    print('zero pose (all angles 0)   :', fk(STD, std_joint, [0, 0, 0])[:3, 3])

2.1 Read the code

  • dh_std and dh_mod are the two matrices of the maths course, written cell by cell. The order of their arguments follows the order of the columns of each table.
  • fk starts from the identity and multiplies the rows from the base to the tool: T = T1 T2 … Tn.
  • The last column of T (T[:3, 3]) is the position of the tool; the top-left 3×3 block is its orientation.
  • The robot is only data: to study another robot, change the table, not the code.
What the output proves

The standard and the modified tables of the same arm give the same tool position (0.479, 0.223, 0.757) — the value found by hand in the maths course — and np.allclose confirms that even the orientation is identical. The zero pose gives (0.83, 0, 0.40): the arm stretched along x at the height of the shoulder.

The two classic bugs
  • Feeding a standard table to the modified matrix (or the reverse): no error, just a wrong robot. Keep the convention in the name of the function.
  • Degrees instead of radians in α: write np.pi / 2 or np.radians(90), never 90.

Key terms

  • DH table
  • homogeneous matrix
  • loop
  • np.allclose
The essentials
  • One function per row (dh_std or dh_mod), one loop that multiplies the rows.
  • The robot is data: change the table, not the code.
  • Check: both conventions give the same pose; the zero pose matches the drawing.

Inverse kinematics in closed form

16 min
You will learn

to code the exact inverse kinematics of the 2-axis arm with its two elbow solutions, to detect unreachable points, and to test it with the round trip FK(IK(x)) = x.

3.1 The formulas

The distance from the base to the target fixes the angle of the elbow (law of cosines); then the direction of the target fixes the shoulder:

cos θ2 = (x² + y² − L1² − L2²) / (2 L1 L2)    θ1 = atan2(y, x) − atan2(L2 sin θ2, L1 + L2 cos θ2)

  • If |cos θ2| > 1 the point is out of reach: return “no solution” instead of crashing.
  • sin θ2 = ±√(1 − cos² θ2): the two signs are the two elbows (up and down).
  • Use atan2, never arccos alone or arctan of a ratio: they lose the quadrant.
"""Closed-form inverse kinematics of the planar 2-axis arm, with both elbow solutions."""
import numpy as np
from arm_fk2 import fk, L1, L2


def ik(x, y, elbow_up=True):
    """Tool position (m) -> joint angles (rad), or None if the point is out of reach."""
    c2 = (x * x + y * y - L1 * L1 - L2 * L2) / (2 * L1 * L2)    # law of cosines
    if abs(c2) > 1:
        return None                                              # too far or too close
    s2 = np.sqrt(1 - c2 * c2) * (-1 if elbow_up else 1)          # the two signs = the two elbows
    theta2 = np.arctan2(s2, c2)
    theta1 = np.arctan2(y, x) - np.arctan2(L2 * s2, L1 + L2 * c2)
    return theta1, theta2

    for target in [(0.537, 0.636), (0.6, 0.2), (1.0, 0.0)]:

        for up in (True, False):
            sol = ik(*target, elbow_up=up)
            if sol is None:
                print('   out of reach (max reach 0.9 m)')
                break
            _, tool = fk(*sol)                                   # round trip: FK(IK(x)) must give x back

                  f'   check FK -> ({tool[0]:.3f}, {tool[1]:.3f})')

3.2 The round trip test

The best test of an inverse model needs no answer key: compute the forward kinematics of the solution and compare with the target. Here both elbows give back (0.537, 0.636) exactly, and the elbow-down solution (29.96°, 45°) is, with rounding, the pose (30°, 45°) of lesson 1. The point at 1.0 m is correctly refused: the reach is 0.9 m.

Which elbow to choose?

A real controller keeps the solution closest to the current pose (smallest joint motion), and checks the joint limits and the obstacles. Switching elbow in the middle of a motion makes the arm flip: never do it while moving.

The Jacobian and numerical inverse kinematics

18 min
You will learn

to compute the Jacobian of any arm with finite differences, and to solve the inverse kinematics of any arm step by step, safely near singularities.

A closed-form inverse model exists only for simple robots. For any other one, the computer searches: from a guess, it moves the joints a little in the direction that brings the tool closer, again and again. It is exactly what the “Build your first robot” workshop does when you press “Send the tool to the ball”.

4.1 The Jacobian by finite differences

Column i of the Jacobian is “how the tool moves when joint i turns a little” (maths course, lesson 9). No need to derive anything: turn joint i by a tiny h, measure how much the tool moved, divide by h. It works for any robot that has a forward model.

4.2 The search: damped least squares

At each step: error e = target − position; correction Δq = JT (J JT + λ² I)−1 e; new q = q + Δq, kept inside the joint limits. The small λ (the damping) keeps the step small near a singularity, where J JT can no longer be inverted (singularities course, lesson 8).

"""Numerical inverse kinematics for any arm: Jacobian by finite differences + damped least squares."""
import numpy as np
from arm_dh import fk, STD, std_joint

LIMITS = np.radians([[-170, 170], [-10, 170], [-150, 150]])


def position(q):
    return fk(STD, std_joint, q)[:3, 3]


def jacobian(q, h=1e-6):
    """3 x n matrix: column i = how the tool moves when joint i turns a little."""
    p0 = position(q)
    J = np.zeros((3, len(q)))
    for i in range(len(q)):
        dq = np.array(q, dtype=float)
        dq[i] += h
        J[:, i] = (position(dq) - p0) / h
    return J


def ik(target, q0, damping=0.01, tol=1e-4, max_iter=100):
    q = np.array(q0, dtype=float)
    for it in range(max_iter):
        error = target - position(q)
        if np.linalg.norm(error) < tol:
            return q, it
        J = jacobian(q)
        # damped least squares: dq = J^T (J J^T + lambda^2 I)^-1 error  (safe near singularities)
        dq = J.T @ np.linalg.solve(J @ J.T + damping ** 2 * np.eye(3), error)
        q = np.clip(q + dq, LIMITS[:, 0], LIMITS[:, 1])
    return q, max_iter


if __name__ == '__main__':
    np.set_printoptions(precision=3, suppress=True)
    target = np.array([0.479, 0.223, 0.757])           # the tool position of the DH lesson
    q, n = ik(target, q0=np.radians([0, 45, -45]))
    print(f'converged in {n} iterations: q = {np.degrees(q)} deg')
    print('reached position:', position(q), ' error (mm):', round(1000 * np.linalg.norm(position(q) - target), 3))
    # 20 random reachable targets: pick random joint angles, compute the position, then solve back
    rng = np.random.default_rng(1)
    targets = [position(rng.uniform(LIMITS[:, 0] * 0.8, LIMITS[:, 1] * 0.8)) for _ in range(20)]
    ok1 = ok2 = 0
    for p in targets:
        q_sol, _ = ik(p, q0=np.radians([0, 45, -45]))                 # always the same start
        ok1 += np.linalg.norm(position(q_sol) - p) < 1e-3
        for start in [np.radians([0, 45, -45])] + [rng.uniform(LIMITS[:, 0], LIMITS[:, 1]) for _ in range(5)]:
            q_sol, _ = ik(p, q0=start)                                # retry from other starts if needed
            if np.linalg.norm(position(q_sol) - p) < 1e-3:
                ok2 += 1
                break
    print(f'random targets reached within 1 mm, one start     : {ok1} / 20')
    print(f'random targets reached within 1 mm, up to 6 starts: {ok2} / 20')

  • From one fixed start it reaches only 12 targets out of 20: a local search can get stuck against a joint limit, or go towards the other elbow and stop.

5.1 A smooth motion: the degree-5 polynomial

Jumping from one angle to another shakes the arm. The quintic law (modelling course, lesson 9) goes from q0 to q1 in a time T with zero speed and zero acceleration at both ends. Its peak speed, at mid-time, is 1.875 times the average speed: use it to check that the servos are fast enough.

"""A smooth joint trajectory (degree-5 polynomial) and the servo pulses that follow it."""
import numpy as np


def quintic(q0, q1, T, t):
    """Position at time t of a motion from q0 to q1 in T seconds, with zero speed and acceleration at both ends."""
    s = np.clip(t / T, 0.0, 1.0)
    return q0 + (q1 - q0) * (10 * s**3 - 15 * s**4 + 6 * s**5)


def to_pulse_us(angle_deg, offset_deg=0.0, us_min=500, us_max=2500):
    """Hobby servo: 0..180 deg -> 500..2500 microseconds; offset_deg = calibration of the zero."""
    a = np.clip(angle_deg + offset_deg, 0, 180)
    return int(round(us_min + (us_max - us_min) * a / 180))

5.2 Servos: angle → pulse

  • A hobby servo receives a pulse every 20 ms; its width sets the angle: typically 500 µs → 0°, 1500 µs → 90°, 2500 µs → 180° (check the data sheet: many use 1000 to 2000 µs).
  • The servo contains its own motor, gearbox, potentiometer and P controller: you only send the target angle.
  • Each servo is mounted a little off: measure its offset once (send 90°, measure the real angle) and add it in software.
  • Joint angle and servo angle differ: usually servo = 90° + θ (or 90° − θ if it is mounted the other way). Write this mapping in one function, and test it joint by joint.

5.4 The code on both sides

The Arduino only receives three angles per line and moves the servos. All the maths (trajectory, inverse kinematics, offsets) stays in Python on the computer, where it is easy to debug.

// Arduino sketch: receives "a1 a2 a3" (servo angles in degrees, one line per command) and moves 3 servos.
#include <Servo.h>

Servo s[3];
const int PINS[3] = {9, 10, 11};

void setup() {
  Serial.begin(115200);
  for (int i = 0; i < 3; i++) {
    s[i].attach(PINS[i], 500, 2500);     // pulse range in microseconds (check your servo's data sheet)
    s[i].write(90);                       // start in the middle
  }
}

void loop() {
  if (Serial.available()) {
    for (int i = 0; i < 3; i++) {
      int a = Serial.parseInt();          // reads the next integer of the line
      s[i].write(constrain(a, 0, 180));   // never send a servo beyond its range
    }
    while (Serial.available() && Serial.read() != '\n') {}   // drop the end of the line
  }
}
"""Send a smooth trajectory to the 3-servo arm over USB (pip install pyserial numpy)."""
import time
import numpy as np
import serial                                   # pyserial
from arm_traj import quintic

PORT = '/dev/ttyACM0'                           # Windows: 'COM3'; macOS: '/dev/cu.usbmodem...'
OFFSETS = np.array([0.0, -3.0, 2.0])            # calibration of each servo (deg)

with serial.Serial(PORT, 115200, timeout=1) as link:
    time.sleep(2)                               # the Arduino restarts when the port opens
    q_start, q_goal, T, dt = np.array([90, 45, 120.0]), np.array([30, 100, 60.0]), 2.0, 0.02
    t0 = time.time()
    while (t := time.time() - t0) <= T:
        q = np.clip(quintic(q_start, q_goal, T, t) + OFFSETS, 0, 180)
        link.write(('%d %d %d\n' % tuple(np.round(q))).encode())
        time.sleep(dt)                          # 50 commands per second

Level 1 · Beginner1

Pulse for 90° on a 500–2500 µs servo (µs)?

Solution

500 + 2000 × 90/180 = 1500 µs: the middle.

Level 2 · Intermediate2

A servo turns at 300 °/s at most. A quintic motion of 90°: shortest duration T (s)?

Hint

Peak speed = 1.875 × 90 / T ≤ 300.

Solution

T ≥ 1.875 × 90 / 300 = 0.5625 s.

Level 3 · Professional3

Three servos draw up to 1.2 A each at 6 V. Minimum power of the supply (W)?

Solution

3 × 1.2 = 3.6 A; 3.6 × 6 = 21.6 W. Take a margin: 5 A or more.

Check yourself

  1. Why is a servo arm moved along a quintic trajectory instead of jumping to the target?

    It starts and stops with zero speed and acceleration: no shock, no shaking.

  2. Why must the servos have their own power supply?

    They draw peaks of several amperes; the Arduino 5 V pin cannot give them and the board would reset or break.

  3. Why keep the maths in Python and not in the Arduino?

    It is easier to write, test and debug on the computer; the Arduino only needs to move the servos.

Level 1 · Beginner1

2-axis arm, L1 = 0.5 m, L2 = 0.4 m, θ = (90°, 0°). y of the tool (m)?

Solution

Both links point up: y = 0.5 + 0.4 = 0.9 m.

Level 1 · Beginner2

Same arm, θ = (0°, 90°). y of the tool (m)?

Solution

Link 1 along x, link 2 up: tool at (0.5, 0.4).

Level 1 · Beginner3

How many inverse kinematics solutions does the 2-axis arm have for a point strictly inside its workspace?

Solution

2: elbow up and elbow down (one only on the boundary, when the arm is stretched or folded).

Level 1 · Beginner4

A table has the columns α, a, θ, d. Which convention?

  1. Modified DH (DHM)
  2. Standard DH

Solution

The moves along x come first: modified DH.

Level 1 · Beginner5

The 3-axis arm of the course (d1 = 0.40, a2 = 0.45, a3 = 0.38), all angles at 0. x of the tool (m)?

Solution

Stretched along x: 0.45 + 0.38 = 0.83 m (at the height 0.40 m).

Level 2 · Intermediate6

2-axis arm (0.5 m, 0.4 m), target (0.6, 0.2). |θ2| in degrees?

Hint

cos θ2 = (x² + y² − L1² − L2²) / (2 L1 L2).

Solution

cos θ2 = (0.36 + 0.04 − 0.25 − 0.16) / 0.4 = −0.025, so |θ2| = 91.43° (the output of lesson 3).

Level 2 · Intermediate7

Is the point (0.7, 0.6) reachable by the 2-axis arm (0.5 m, 0.4 m)?

  1. No: it is 0.92 m away, the reach is 0.9 m
  2. Yes, with the elbow up
  3. Yes, with the elbow down

Solution

√(0.49 + 0.36) = 0.922 m > 0.9 m: out of reach; cos θ2 would be greater than 1.

Level 2 · Intermediate8

det J of the 2-axis arm is L1 L2 sin θ2. Value at θ2 = 30° (m²)?

Solution

0.5 × 0.4 × 0.5 = 0.1 m². It is 0 at θ2 = 0: the stretched arm is singular.

Level 2 · Intermediate9

Turning joint 2 by 0.001 rad moves the tool by 0.25 mm. Value of this entry of the Jacobian (m/rad)?

Solution

0.00025 m / 0.001 rad = 0.25 m/rad: the finite difference of lesson 4.

Level 2 · Intermediate10

Why add a damping λ in the numerical inverse kinematics?

  1. To avoid huge steps near a singularity
  2. To go faster far from singularities
  3. To respect the joint limits

Solution

Near a singularity J Jᵀ is almost not invertible: without λ the correction explodes. The limits are handled by the clipping.

Level 3 · Professional11

A quintic motion of 60° in 2 s. Peak speed (°/s)?

Solution

Average 30 °/s × 1.875 = 56.25 °/s, reached at mid-time.

Level 3 · Professional12

A servo maps 0–180° to 500–2500 µs. Pulse for 45° (µs)?

Solution

500 + 2000 × 45 / 180 = 500 + 500 = 1000 µs.
